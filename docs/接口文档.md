# 接口文档（唯一入口 · 第三方与二次开发的契约面）

> **本文是什么**：所有「外部可以依赖什么」的契约——内容包格式、皮肤包格式、GAL 页协议、代码扩展点、沙箱权限。
> **本文不是什么**：不讲怎么做一个 mod（那是 `MOD开发指南.md`），不讲运维（那是 `维护手册.md`）。
> **权威声明**（2026-09-12 文档精简）：**凡第三方要依赖的字段与协议，以本文为准**。
> 本文取代 `PLUGIN_SDK.md` 的契约地位（该文件保留为 Phase 3 历史记录与 SDK 发行物）；
> 皮肤包的**深层细节**（虚拟主机、postMessage 全流程、UI 素材目录）见 `皮肤包接口规范-v1.md`，本文只给契约总表。
> **兼容承诺**：本文列出的 schema 字段与钩子点，在 v1.x 内**只增不改不删**。

---

## 0. 接口全景与权威归属

| 接口 | 面向谁 | 形态 | 本文位置 |
|---|---|---|---|
| 内容包 `robot-pack-v1` | 内容作者（零代码） | 目录 + JSON | §3（完整契约） |
| 皮肤包 `launcher-skin-v1` | 外观作者 | 目录 + manifest + 页面 | §4（总表）/ 皮肤规范（细节） |
| GAL 页协议 | 前端/演出作者 | HTTP + WebSocket + JS 钩子 | §5（完整） |
| 代码扩展 `ToolCard` | Python 开发者 | 在进程内注册 | §6.1 |
| 工具包沙箱 | 第三方代码包 | pack.json `permissions` | §6.3 |
| CLI/运维工具 | 使用者 | 命令行 | `维护手册.md` |

**三种扩展方式的成本从低到高**：内容包（改 JSON）→ 皮肤包（改页面）→ 工具包（写 Python，**默认不加载**）。
**「无包 = 原行为」**是全项目的回落铁律：任何接口缺省都必须等于"这个包从未存在过"。

## 1. 核心版本与兼容承诺

- 当前核心接口版本：**`CORE_API_VERSION = "1.0.0"`**（定义于 `qq-bot/core/packs.py`，由 `build/build_release.ps1` 在构建时提取写进发行说明）。
- 包清单里用 `compat.core_api`（如 `">=1.0"`）声明适配版本。**v1 仅记录不强制**：版本不符不拒载。
- 未来引入破坏性变更时升次版本号，并在本文标注迁移说明。

---

## 2. 目录约定（三层分离 · 谁覆盖谁）

```
<安装根>/
├─ qq-bot/plugins/        框架自带插件      ← 更新发行版时**会被覆盖**，不要放自己的东西
├─ qq-bot/packs/          随仓示例内容包    ← 会被覆盖；活示例与测试夹具
├─ data/plugins/          第三方代码插件    ← 永不被覆盖；**自动发现**（§6.4）
├─ data/packs/            内容包（用户安装） ← 永不被覆盖，**放进来即用**
└─ launcher/web/skins/    皮肤包            ← 永不被覆盖
```

**同名包 `data/packs/` 优先**：两个包根各扫一层（只认"含 `pack.json` 的目录"），同名清单先到先得——用户包覆盖随仓示例。
**缓存**：按目录 mtime 进程内缓存；改包内文件后**重启 bot**，或调 `core.packs.reload()`。

## 3. 内容包 `robot-pack-v1`（完整契约）

### 3.1 `pack.json` 字段

```json
{
  "spec": "robot-pack-v1",
  "name": "author.name",
  "version": "1.0.0",
  "type": "card | voice | item | emotion | world | tool | gal",
  "title": "给人看的标题",
  "author": "作者",
  "license": "CC0-1.0",
  "compat": { "core_api": ">=1.0" },
  "permissions": [],
  "limits": { "timeout_s": 5, "memory_mb": 256, "calls_per_min": 60, "result_kb": 64 }
}
```

| 字段 | 必需 | 校验 |
|---|---|---|
| `spec` | ✓ | 必须等于 `"robot-pack-v1"` |
| `name` | ✓ | 点分小写 `^[a-z0-9][a-z0-9_-]*(\.[a-z0-9][a-z0-9_-]*)+$`；双根内唯一（data 覆盖） |
| `version` | ✓ | 语义版本三段 `x.y.z` |
| `type` | ✓ | 上表 7 类之一；**未知 type 跳过不炸** |
| `title` / `author` / `license` | – | 展示用字符串，不校验 |
| `compat.core_api` | – | v1 仅记录 |
| `permissions` / `limits` | – | **仅 `type=tool` 有意义**，见 §6.3；缺省 = 零能力 |

- **未知附加键**：允许携带规范外键，加载器只读上表字段、其余忽略不报错。给机器读的说明键建议 `_` 前缀（如 `_comment`），与未来规范字段天然不冲突。
- 读取容忍 BOM（utf-8-sig），**发布建议无 BOM**。
- 单文件读取上限 **8 MB**（防呆）；包内相对路径 resolve 后必须仍在包目录内（**路径穿越整包拒载**）。

### 3.2 `type=card`（人设卡 + 台词 + 语音 + 立绘 + 差分：一个包=一张完整角色）

```
packs/example.sakura/
  pack.json              type=card，附 "card":{"key":"sakura", ...启动器展示字段(可选)}
  card.json              人设卡（chara_card_v2，与 data/personas/*.json 同格式）
  quotes.json            签名台词 {"quotes":[{"q":"…","by":"…"}]}            （可选）
  voice.json             音色（格式同 §3.3）                                  （可选）
  sprites/manifest.json  {"expressions":["词",…],"map":{"基调词":"素材词"}}    （可选）
  sprites/full|bust|diff/<键>_<词>.webp                                       （可选，见下）
  world.json             世界观段（可内嵌，也可独立 type=world 包）            （可选）
```

| 子段 | 说明 |
|---|---|
| `card.key` | 必需。卡键 `^[A-Za-z0-9_-]+$`：persona 回落键、立绘 URL 键、`cards.json` 的 key |
| `card.name/cls/star/uni/desc` | 可选，启动器卡片墙展示字段；缺省 `cls="MOD", star=4, uni="PACK"` |
| `card.json` | 必需。`{"spec":"chara_card_v2","data":{…}}`，字段照 `qq-bot/data/personas/_template.json`。**建议带 `universe`**（关联场景词库、世界观注入、同源角色互认） |
| `quotes.json` | 可选。进 `/gal/content.json` 的 `quotesByCard[card.key]` |
| `sprites/manifest.json` | `expressions`=差分菜单词（**卡自带 `sprite_expressions` 时以卡为准**，此处是回落源）；`map`=基调词→素材词（前端拼 `<key>_<素材词>.webp` 探测） |
| `sprites/full\|bust\|diff/` | 素材目录。**命名约定**：`<卡键>_<词>.webp\|png`（全身/半身/差分同名族；无词的基图为 `<卡键>.webp`）。**v1 边界**：运行时不自动搬运包内素材，实际立绘位在 `<安装根>/launcher/cards/`（见 §3.9） |

**卡包接线点（全部向后兼容，无包=原行为）**：
1. **persona 回落**：`data/personas/<key>.json` 不存在时经包 `card.json` 加载（带 `source:"pack"` 标记）；**本地卡永远优先**。
2. **台词外置**：包 quotes 打底 → `data/quotes.json` 整键覆盖（用户数据层）。
3. **语音合并**：见 §3.3（`setdefault`，内置表优先）。
4. **差分菜单**：卡无 `sprite_expressions` → 回落包 `sprites/manifest.json` 的 `expressions`。
5. **启动器卡数据**：`tools/export_cards.py` 扫包 → **只追加**新键进 `data/cards.json`（免重编译 exe）。

### 3.3 `type=voice`（独立语音包；卡包也可内嵌 `voice.json`）

```json
{ "key": "mysound", "name": "我的音色", "lang": "zh", "personas": ["角色显示名"],
  "gpt": "C:\\abs\\model.ckpt", "sovits": "C:\\abs\\model.pth",
  "ref_dir": "C:\\abs\\refs", "refs": "voice_refs.json",
  "emo_refs": {"战斗": "参考音条目名"} }
```

- 键取 `voice.json.key` > `card.key` > 包名末段。
- `gpt` / `sovits` / `ref_dir` **必须是绝对路径**，相对路径条目**跳过+warning**（GPT-SoVITS 权重属 `tools/`，gitignored：**公开发行只带格式与文档、不带权重**）。
- 合并纪律：`setdefault` 进 `VOICES`——**内置表优先**，同名键（如 `amiya`）不被包覆盖。
- `emo_refs` 的键用 9 类口径（战斗/高冷/讥讽/温柔/无语/娇嗔/疑问/纯H/傲娇），缺类回「默认」参考音。

### 3.4 `type=item`（道具 mod）

```json
"items": [ { "name": "魔法茶杯", "label": "魔法茶杯", "note": "会自己续杯", "ttl_min": 5 } ]
```

| 字段 | 校验 |
|---|---|
| `name` | 消毒（去空白与结构符、限 8 字）后非空 |
| `label` | 非空且 ≤12 字（展示名） |
| `note` | 可选，默认效果文案（≤80 字） |
| `ttl_min` | >0 数字（默认时效分钟） |

- 语义：目录项=**给默认呈现**；**不改变开放性**——目录外道具照旧按开放集登记。
- 内置道具不受目录影响。

### 3.5 `type=world`（世界观/世界书，酒馆式；可独立包或内嵌卡包）

```json
{ "universe": "stellar-teahouse",
  "entries": [ { "keys": ["触发词"], "text": "设定文本", "always": true, "priority": 0 } ] }
```

| 字段 | 说明 |
|---|---|
| `universe` | 世界观键——与 persona 卡 `universe`、`data/universe_roles.json`、`qq-bot/data/scenes.json` 对齐 |
| `entries[].keys` | 触发词列表（**v1 未实现关键词触发**，schema 预留） |
| `entries[].text` | 设定文本（非空才收录） |
| `entries[].always` | true = 常驻注入 |
| `entries[].priority` | 整数，降序稳定排序（同优先级保持文件序，跨包合并后全局排序） |

- **v1 行为**：仅注入 `always:true` 条目，格式 `\n\n【世界观设定】\n- text`，整块上限 **800 字**（超限截断+注释）。无 world 包/卡无 universe = 零注入。
- **v2 路线**：keys 关键词触发匹配（命中近期上下文才注入）；`always` 条目行为不变，纯增量。

### 3.6 `type=emotion`（额外情绪 mod）

```json
"tones": [ { "word": "得意", "sprite_word": "proud", "voice": { "temp": 1.0, "speed": 1.05, "semi": 0.5 } } ]
```

| 字段 | 说明 |
|---|---|
| `word` | 情绪基调词（≤6 字，对齐【基调：两三字】口径） |
| `sprite_word` | 可选：差分素材词 → 进 `spriteMap[card.key]`（仅 card 包的 tones） |
| `voice` | 可选：`temp` 温度 / `speed` 语速 / `semi` 半音偏移；**允许空 `{}`** = 只扩 sprite/文案层 |

- 带完整 voice 的 tone 词 **setdefault 合并进 `EMO_PARAMS`**（内置 9 类优先）；空 voice 不进声调表。
- **口径边界**：LLM 情绪分类的 9 类口径**暂不扩**——新增词走【基调】自标直通路径。

### 3.7 `type=tool`（工具包=代码，**默认不加载**）

```json
"tools": [ { "entry": "relative.py", "cards": ["ns.name"] } ],
"permissions": ["fs.read:./assets/**", "net:api.example.com"],
"limits": { "timeout_s": 5, "memory_mb": 256, "calls_per_min": 60, "result_kb": 64 }
```

- `entry` 包内相对路径；`cards` 声明该 entry 提供的 ToolCard 名（`namespace.name`）。
- **默认不执行任何 python**：`PACKS_ENABLE_PY` 显式开启才装载。默认路径**零 import、零执行、零子进程**。
- 权限与沙箱契约见 §6.3。

### 3.8 `type=gal`（GAL 舞台包 · 2026-09-12 定案）

把「**舞台长什么样**」从人设卡与皮肤里独立出来——差分像素与背景归舞台，词表归角色，外壳归皮肤。

```json
{"spec":"robot-pack-v1","type":"gal","name":"author.stage-room","version":"1.0.0",
 "title":"","author":"","license":"私用","compat":{"core_api":">=1.0"},
 "stage":{"default_bg":"room_night","bg_alt":"room_day","bg_by_scene":{"天台":"rooftop"}}}
```

```
<pack>/
  pack.json
  bg/<背景id>.<png|jpg|webp>          ← 背景（变化轴 = 场景）
  sprites/diff/<卡键>_<词>.webp        ← 差分（变化轴 = 卡键 × 词）
  sprites/manifest.json               ← 可选：map 覆盖卡包同名键
```

| 字段 | 说明 |
|---|---|
| `stage.default_bg` | 无场景命中时的默认背景 id（对应 `bg/<id>.<ext>`） |
| `stage.bg_alt` | 默认背景加载失败时的备选 |
| `stage.bg_by_scene` | `{场景词: 背景id}`；场景词来自 lifesim 的 `scene`（模型自由生成的文本） |

- **场景匹配必须是三级**：`精确 → 包含 → default`。`scene` 是自由文本，`天台上看星星` 不会与 `天台` 等值，只做等值匹配等于没做。
- **素材解析优先级**（沿用"包打底 → 本机覆盖"）：`随仓示例包（零 IP 占位图） < data/packs/<舞台包> < launcher/cards/（本机私有素材）`。
- **命名约定复用** `sprites/full|bust|diff/<键>_<词>.webp`——既有素材**纯拷贝入包，零改名**。
- 三人设卡变化轴正交：卡包给**词**（`sprite_expressions` / `map`）、舞台包给**图**、皮肤包给**壳**（配色/控件/布局）。

> **实现状态（2026-09-12 起：已实现）**：`gal` 已在 `VALID_TYPES` 中，索引与解析均已落地。
> 服务出口：**`GET /gal/stage/<包名>/<包内相对路径>`**（见 §5.1）——背景与差分像素都由它提供；
> 背景 id **文件不存在时不会出现在索引里**（前端因此走 CSS 渐变兜底，而不是拿到必然 404 的地址）。
> 差分词表：`sprite_words()` 按 `舞台包 sprites/diff/` → `launcher/cards/bust4w` **多根扫描**，包在前。
>
> **本机私有素材的现成产出**：`qq-bot/tools/export_content_packs.py` 会把
> `launcher/cards/` 的立绘（差分/半身/全身）与皮肤目录里的背景打成
> `release/local-content/arknights-stage-<日期>.zip`——**逐字节纯拷贝、零改名**，
> 解开把 `packs/local.stage/` 放进 `data/packs/` 即用。
> 它**故意不写 `sprites/manifest.json` 的 map、也不声明 `card.key`**：卡包已经声明了各自的
> "词→素材词"映射，舞台包再写一份就是第二个事实源（这正是本节要避免的事）。

### 3.9 坏包自查（包没生效时先看这里）

- **bot 侧**：坏包被跳过的原因走 loguru warning → bot 控制台 + `<安装根>/data/bot.log`（按包名 grep）。
- **launcher 侧**：启动器脚本异常（含皮肤目录缺失回落 generic）留痕 `<安装根>/launcher/boot_err.log`。
- 常见原因：`pack.json` 非 JSON / `spec` 缺失或值不对 / `name` 不满足点分小写 / `version` 非三段 / 未知 `type` / 路径穿越。**一律跳过该包，不会半装载**。
- **立绘不显示**：包内 `sprites/` 素材 **v1 无运行时消费**——真实立绘位是 `<安装根>/launcher/cards/`（全身 `<key>_full.png`、半身 `bust4w/<key>.webp`、差分 `bust4w/<key>_<词>.webp`）。素材需按此命名放入该目录。缺图由前端回退链兜底（差分→默认半身→全身→首字占位），**无立绘的卡被启动器网格过滤**（不报错）。

## 4. 皮肤包 `launcher-skin-v1`

> 本节是**契约总表**；虚拟主机建立过程、postMessage 全流程、`ui/` 素材目录等细节见 `皮肤包接口规范-v1.md`。

### 4.1 `manifest.json` 字段（UTF-8 无 BOM）

| 字段 | 类型 | 说明 |
|---|---|---|
| `spec` | string | 固定 `launcher-skin-v1` |
| `name` | string | 皮肤标识（= 目录名，`data/launcher.json` 的 `skin` 键取值） |
| `title` | string | 显示名（设置页下拉） |
| `entry` | string | 入口页，相对皮肤目录 |
| `palette.bg/fg/accent/muted` | string | 四色（HEX）；`bg` 会用于 WPF 窗口背景纯色刷 |
| `statePath` | string | 运行时 state.json 相对路径（信息性；轮询以**页面所在目录**为准） |
| `operaPage` | bool | **皮肤是否自带「干员」页**（可空，缺省 false）。true = 框架顶栏「干员」与 `cmd:"operators"` 都打开**皮肤自己的**干员视图（推 `page:"opera"`，由皮肤渲染）；false/缺省 = 用框架原生干员页兜底。皮肤自绘的干员界面优先于框架那张 |
| `author` | string | 作者（可空） |
| `license` | string | 许可标识 |
| `note` | string | 备注（可空） |

### 4.2 虚拟主机（页面里唯一可以用的绝对地址形式）

| 主机名 | 映射到 | 用途 |
|---|---|---|
| `https://app.local/…` | `launcher/web/` | 启动器页面与素材；skins 子树天然可达 |
| `https://cards.local/…` | `launcher/cards/` | 人设立绘（`bust4w/` 半身+差分、`fullw/` 全身） |

> 页面内引用素材一律用 `app.local` 绝对地址或皮肤目录内相对路径；
> `http://127.0.0.1:8080` **仅用于 GAL 页与 bot HTTP 通道**。

### 4.3 `state.json` 数据契约（PS → 页面的主通道）

推送：启动器约每 **3 秒**整体覆写活动皮肤目录下的 `state.json`（非原子写；轮询侧解析失败静默跳过本帧）。
轮询：页面脚本每 **1 秒**取**页面同目录**的 `state.json?t=<毫秒时间戳>`——**`?t=` 防缓存，不可省略**。

| 字段 | 类型 | 说明 |
|---|---|---|
| `__push` | bool | 恒 `true`（推送标记） |
| `stamp` | int | 自增序号（诊断） |
| `pid` | int | 启动器 PID（变化 = 出现双实例） |
| `time` | string | `yyyy/MM/dd HH:mm` |
| `scene` / `doing` / `mood` / `plan` | string | 来自 `life_state.json` |
| `dialog` | string | `doing` 去掉 `【…】` 后的对话行 |
| `wake` | string | 下次心跳描述 |
| `name` / `star` / `idtext` | string | 主人昵称 / 星级 `★×n` / `<卡名> · <阵营>` |
| `portrait` | string | 当前人设立绘 URL（无则空串） |
| `page` | string | 页面指令：`home`/`opera`/`detail`（`cfg`/`log`/`state` 是 WPF 原生页，web 不可见） |
| `op` | object | `{active: bool, text: string}` 操作进行中标志 |
| `svc` | object | 四服务灯 `{engine, embed, napcat, bot}` 四 bool（true=运行中）；旧版无此字段时页面保持灰灯 |
| `cards` | array | 卡片墙载荷；**无可用立绘的卡被过滤** |
| `lang` | string | 界面语言（`zh`/`en`，缺省 `zh`）；皮肤据此换文案，并在跳 GAL 页时带 `?lang=` |

`cards[]` 单条：`key` / `name` / `cls` / `uni` / `desc` / `starText`（★ 文本，**不是** `star` 数值）/
`img`（半身 `https://cards.local/bust4w/<key>.webp`）/ `big`（全身 `fullw/<key>.webp`）/
`rar`（星级角图 `https://app.local/skins/<skin>/ui/ark/rarity_<n>.png`；**皮肤感知**：generic 皮肤时为空串，前端判空跳过）。

### 4.4 命令通道（JS → PS）

```js
window.chrome.webview.postMessage({ cmd: '<cmd>', data: '<字符串负载>' });
```

**`data` 恒为字符串**（`setpersona` 的卡键就放这里，不要嵌套对象）。

| cmd | data | 行为 |
|---|---|---|
| `start` | 空 | 启动全部（引擎→记忆→NapCat→bot 步进机） |
| `stop` | 空 | 停止全部（含 LLM，释放显存） |
| `stopbot` | 空 | 仅停机器人（LLM 保持） |
| `exit` | 空 | 停止全部后关窗退出 |
| `opera` / `home` | 空 | 切主页 web 视图并推 `page:"opera"` / `page:"home"` |
| `operators` / `deps` / `about` | 空 | 打开**干员 / 组件 / 关于**页（web 被整页遮盖）。⚠️ 干员**不是**"一律开框架页"：皮肤自带干员页（`manifest.operaPage: true`）时开**皮肤自己的**视图，框架原生页只在皮肤没提供时兜底（分层定案见 `docs/皮肤包接口规范-v1.md` §9） |
| `cfg` / `plugins` / `log` / `state` | 空 | 打开 WPF 原生设置页 / 插件页 / 日志页 / 状态页（web 被遮盖） |
| `setpersona` | **卡键字符串** | POST `http://127.0.0.1:8080/launcher/persona`（body `{"name":"<卡键>","uid":"<主人QQ>"}`）；bot 在线切换；通道不通时兜底写 `persona_select.json`（重启生效） |

> 保留字 `diag`（整条消息落 `web_diag.log`）、`hb`（心跳）——皮肤无需使用。
> 备用 URL 通道（`?cmd=<cmd>&d=<urlencoded>`）仅内置方舟样板在用，新皮肤不必依赖。

### 4.5 皮肤**必须**提供的两个全局函数

启动器会直接 `ExecuteScriptAsync("showWebBlock('…')")` 调用它们：

```js
window.showWebBlock = function (text) { /* 全屏遮罩 + ⚠ 横幅；文案里的 ⚠（…）装饰自行剥离，空值用默认文案 */ };
window.hideWebBlock = function () { /* 同时收起遮罩与横幅 */ };
```

`op.active` 轮询与直呼**互为冗余**（任一先到都生效）。参照实现：`launcher/web/app.js`。

### 4.6 GAL 素材口的皮肤覆盖链

皮肤可在 GAL 客户端脚本**加载之前**定义 `window.GAL_SKIN` 覆盖素材口：

```js
window.GAL_SKIN = { assets: { bgDefault: 'https://app.local/skins/<skin>/img/x.png' } };  // 与 ASSETS 同形
```

**覆盖先后（重要）**：`GAL_SKIN.assets` 在脚本载入时同步 `Object.assign`；`/gal/content.json` 是**启动后异步拉取、后到覆盖**——content.json 携带的 `quotesByCard` / `quoteFallback` / `spriteMap` **三键**会覆盖 `GAL_SKIN.assets` 里的同名键（**仅此三键**，背景等其余素材键不受影响）。

### 5.1 HTTP 路由

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/gal` | GAL 页本体（`FileResponse` **launcher/web/gal.html**；文件缺失返回说明文字而非 500） |
| GET | `/gal/assets/{name}` | 同目录静态资源，**白名单** `{gal.js, gal.css}`（防目录穿越） |
| GET | `/gal/stage/{name:path}` | **舞台素材**（`type=gal` 包内的 `bg/`、`sprites/diff/`）。形如 `<包名>/bg/room.png`；三重校验：包必须存在且为 `gal` + resolve 拦路径穿越 + 文件必须存在。非 gal 包、穿越、缺文件一律 404 |
| GET | `/gal/content.json` | 内容索引：`{quotesByCard, quoteFallback, spriteMap, stage}`。**既有三键语义一字未改**，`stage` 是 2026-09-12 T14 的增量键（舞台包背景与场景映射，见 §3.8）。顶层键清单由审计 K 项对着 `core/packs.py` 的 `_build_content()` 核验——改载荷就必须同步改这行 |
| GET | `/gal/state` | 当前生活/人设状态快照 |

| GET | `/gal/history` | GAL 回想轮次（JSONL） |
| POST | `/gal/tts` | body `{text, tone}` → 语音（base64）；供页面按页请求 |
| WS | `/gal/ws` | 帧协议，见 §5.2 |
| POST | `/launcher/persona` | body `{"name":"<卡键>","uid":"<主人QQ>"}`（启动器 `setpersona` 用） |

### 5.2 WebSocket 帧协议（`/gal/ws`，单连接 + token 鉴权）

**鉴权**：连接后限时内必须发 `auth`，超时收 `err{reason:"auth timeout"}`；已有连接时新连接收 `err{reason:"busy"}`（**单连接**语义）。

| 方向 | 帧 | 说明 |
|---|---|---|
| 入 | `{type:"auth", token}` | 首个必发；token 见 `data/webgal_token.txt` |
| 入 | `{type:"msg", text}` | 用户发言（等价于在聊天模式说话） |
| 入 | `{type:"mode", mode}` | 切模式 `gal` / `qq` / `chat` |
| 入 | `{type:"ping"}` | 心跳 |
| 出 | `{type:"auth_ok"}` | 鉴权通过 |
| 出 | `{type:"reply_start"}` | 一轮开始（前端清队/停上一轮语音） |
| 出 | `{type:"seg", kind, text, …}` | 正文段；`kind ∈ text \| action \| slice` |
| 出 | `{type:"sprite", emotion}` | **每轮必发**：有词=切该差分；空=客户端回默认半身（防上轮残留） |
| 出 | `{type:"state", …}` | 状态快照 |
| 出 | `{type:"reply_end", mode}` | 一轮结束 |
| 出 | `{type:"err", reason}` | `busy` / `auth timeout` / `idle timeout` / `bad_json` / 轮内异常 |

> `sprite` 帧的取值优先级：`_SPRITE_LAST`（agent 自标【立绘：词】独立自决位）> `_TONE_LAST`（【基调】）。

### 5.3 素材口 `ASSETS`（GAL 客户端顶部，唯一换素材处）

| 键 | 含义 |
|---|---|
| `bgDefault` | 默认背景 URL |
| `bgAlt` | 默认背景失败时的备选 |
| `bgByScene` | `{场景: 背景URL}`；由舞台包 `stage.bg_by_scene` 填充（2026-09-12 T14 起**不再是空钩子**） |
| `charColor` | 姓名牌/主按钮色 |
| `bustBase` | 半身立绘 baseURL（`https://cards.local/bust4w/`） |
| `fullBase` | 全身立绘 baseURL（`https://cards.local/fullw/`） |
| `spriteMap` | `{卡键: {基调词: 素材词}}`，前端拼 `<卡键>_<素材词>.webp` 探测 |
| `quotesByCard` | 分卡台词（**运行期挂在 ASSETS 上**，故 `GAL_SKIN.assets` 可覆盖）；再由 `/gal/content.json` 的 `quotesByCard` 合并覆盖 |

> ⚠️ **`quoteFallback` 刻意不在上表**：它是 `/gal/content.json` 的第四键，落点是模块变量
> `QUOTES_FALLBACK`，**不经 `ASSETS`**——所以皮肤写 `GAL_SKIN.assets.quoteFallback` **不会生效**
> （读点在 `rollQuote`：`ASSETS.quotesByCard[卡键] || QUOTES_FALLBACK`）。要换兜底台词请走内容包 /
> `data/quotes.json`。这条能力缺口是否开放给皮肤，见 `docs/遗留任务.md` A10。
> 本表与 `launcher/web/gal.js` 的键集合由审计 **K 项字段级**双向核对（代码侧也收运行期 `ASSETS.x =` 赋值键）。

**回退链**：差分 `bust4w/<键>_<词>.webp` → 默认半身 `bust4w/<键>.webp` → 全身 `fullw/<键>.webp` → 首字占位；背景失败 → CSS 渐变兜底。**缺图是常态，不报错**。

**场景匹配是三级（2026-09-12 T14 落地）**：`精确 → 最长键包含 → 默认图`。
因为 `scene` 是 lifesim 让模型**自由生成**的文本（如「天台上看星星」），而 `bg_by_scene` 的键是人写的短词（「天台」）——
只做等值匹配等于没做。最长的被包含键优先（键越长越具体，「天台」胜过「天」）。

### 5.4 Live2D / 外部渲染器钩子

页面在 GAL 客户端脚本**加载之前**定义：

```js
window.GAL_RENDERER = { init(stage), onFrame(seg), onStop() };
```

- `init(stage)` 启动时调用一次（`stage` = `#stage` DOM；渲染器自建图层/加载模型）
- `onFrame(seg)` 每个段到达时调用；返回 `false` 或抛异常 = **该段回落内置打字机/页队列**（保守回退，绝不卡轮）
- `onStop()` 换轮/清队时调用
- **未定义 = 全部走原路径**，行为与历史版本完全一致

## 6. 代码级扩展

### 6.1 `ToolCard` 契约（`agent/registry.py`）

```python
from agent.registry import register, ToolCard, FAIL_RETURN_NONE, FAIL_RAISE

@register(name="ns.name", description="能力描述", failure=FAIL_RETURN_NONE, needs_llm=False)
async def my_tool(arg): ...
```

| 字段 | 说明 |
|---|---|
| `name` | 全局唯一，点分命名空间；同名注册抛 `ValueError`（先 `unregister`） |
| `description` | 写给人与感知装配看 |
| `fn` | 执行函数（async/同步皆可；`None` = 占位/已注销） |
| `failure` | `FAIL_RETURN_NONE`（失败按"没拿到"） / `FAIL_RAISE`（失败抛异常，调用方自决） |
| `needs_llm` | 执行是否依赖 LLM（触发判定用，**不是**选路依据） |

> **铁律 #1（注册表存在的前提）**：注册表是**能力清单，不是选路器**。
> 触发仍由消息判定 / agent 教学决定；**禁止让模型按注册表自由选工具**（不做 LLM function-calling）。
> `all_tools()` 返回副本，供感知装配遍历。

### 6.2 稳定钩子点索引

| 钩子 | 位置 | 说明 |
|---|---|---|
| 后台循环 | `bot.py` 的 `_start_background_loops` / `plugins/debug.start_background_loops_async` | 自定义循环注册样板（幂等纪律） |
| special 标记协议 | `core/special.py` 的 `apply_agent_markers` / `apply_owner_facts` | 状态登记/解除=**agent 自决标记**；机器只存事实不代写演出 |
| GAL 帧协议 | `plugins/webgal`（§5.2） | 前后端唯一的演出通道 |
| `/gal/content.json` | `core/packs.content_index()` | 台词/差分映射数据源 |
| 皮肤包 | §4 + `皮肤包接口规范-v1.md` | manifest / state / postMessage / 虚拟主机 / `GAL_SKIN` |
| Live2D renderer | §5.4 | 演出接管点 |
| ToolCard | §6.1 | 代码级能力注册 |
| 内容包发现 | `core/packs.py`（`discover` / `by_type` / `content_index` / `voice_index` / `world_index` / `items_index` / `tones_index`） | 索引视图 |

**铁律对齐**：机器只做五件事——协议标记剥离、控制码解析、**权限边界**、时间窗兜底、事故级红线。
其余（说什么、怎么做、要不要配图、要不要开思考）**一律 agent 自决**。

### 6.3 工具包沙箱契约（`type=tool`）

**现状**：`PACKS_ENABLE_PY` **默认关闭**——关闭时连 import 都不做，普通用户装数据包零风险。
开启后工具包在**独立 AppContainer 子进程**中执行（工作项 S4，可行性已实测）。

> ⚠️ **当前实现边界（2026-09-12 实测核对）**：上面这套沙箱与权限**尚未落地**——`core/packs.py` 目前
> **不读** `permissions`（全仓 0 引用），`load_tools()` 只按 `tools[].entry` 装载 entry。
> 也就是说：**声明 `permissions` 现在是"写给人看 + 为将来对齐"，不会真的拦你**；真正的强制力要等 S4
> 落地（`docs/S4-沙盒与声明式权限-spec-2026-09-12.md`）。这道边界写在这里，是因为"文档承诺、代码没有"
> 比"没写"更危险——第三方作者会以为自己被保护着。**建议仍按词表如实声明**：将来 S4 上线时，
> 没声明的包会立刻失去能力（而不是被静默放行）。

**权限词表**（`permissions`，缺省 = `[]` = 零能力）：

| 能力词 | 含义 | 强制力 |
|---|---|---|
| `fs.read:<模板>` | 只读；resolve 后必须落在模板内 | **内核（ACL）** |
| `fs.write:<模板>` | 可写；未声明即拒 | **内核（ACL）** |
| `net:<host>[:<port>]` | **声明"要访问谁"**；子进程网络恒为 0，请求由**主进程代取**并校验白名单 | 结构（主进程校验） |
| `llm` | 允许经主进程代理调用模型（**凭据不出主进程**） | 结构 |
| `env:<NAME>` | 允许读指定环境变量 | 结构 |

- 模板规则：`./` 开头相对包目录；`*` 段内通配、`**` 跨段；**只有白名单，无否定符**；装载前解析为绝对路径并打 ACL（运行期不做字符串比较，天然免疫 `..` 与符号链接绕过）。
- `limits`：`timeout_s`（默认 5）/ `memory_mb`（256）/ `calls_per_min`（60）/ `result_kb`（64）。**核心侧设硬顶，包不能给自己放宽**。
- **不提供** `exec`（派生外部程序）/ `process` / `registry` / `gui` / `clipboard` / `inject`——这些需求应由主进程提供受控通道。
- 失败语义：沙箱不可用时**一律 fail-closed**（工具包不执行），**绝不退回同进程 `exec_module`**。

### 6.4 目录约定：第三方代码插件放哪

| 类型 | 位置 | 更新发行版时 | 装载方式 |
|---|---|---|---|
| 框架插件 | `qq-bot/plugins/` | **会被覆盖** | `pyproject.toml` 的显式 13 项清单 |
| **第三方代码插件** | `data/plugins/` | **永不被覆盖** | **自动发现**（2026-09-12 S3 起）：子包（含 `__init__.py` 的目录）与单文件 `.py` 都支持 |
| 内容包 | `data/packs/` | 永不被覆盖 | `core.packs` 双根扫描 |
| 皮肤包 | `launcher/web/skins/` | 永不被覆盖 | 启动器按 `data/launcher.json` 的 `skin` 键选 |

`data/plugins/` 的装载纪律（三条，**都是踩过的坑**）：

1. **坏插件不带崩 bot**：逐个装、逐个隔离，装不上的记 warning 后继续。
2. **`nonebot.load_plugin()` 不抛异常**——它在内部吞掉导入错误、只打一行
   `[ERROR] nonebot | Failed to import "x"`，然后照常返回。所以判定"是否真装上"**必须比对
   装载器登记表的前后差集**，不能靠 try/except。（本框架第一版据此把坏插件报成 `loaded`，日志在说谎。）
3. **路径是 append 而非 insert 到首位**：插到首位会让一个叫 `json.py` 的插件**遮蔽标准库**——
   那是最难查的一类故障。代价只是"与标准库同名时插件不生效"，可接受。

> 插件名以**模块末段**为准（放在 `data/plugins/my_thing/` 的插件名是 `my_thing`，
> 不是 `data.plugins.my_thing`）。目录名以 `.`/`_` 开头会被跳过（约定：下划线开头是私有/临时）。
>
> **插件里要起后台任务，请用 `core.bgtasks.spawn(coro)`，别裸调 `asyncio.create_task`**：
> asyncio 对任务只持**弱引用**——不保存返回值，任务可能在两次 await 之间被 GC 回收，
> 表现为**静默不再运行**（没有异常、没有日志）。`spawn` 会把引用留到任务结束，并给失败的
> 后台任务记一行 debug 线索。本框架自己踩过这个坑（看门狗/生活模拟等六个常驻循环一度都是裸调），
> 审计 **N 项**会扫出裸调。

### 6.5 本机内容覆盖表：特殊层级的展示名与效果文案

**能力与内容的分界**（2026-09-12 全开源裁决后确定）：

| 侧 | 内容 |
|---|---|
| **框架（代码，公开）** | 状态 kind **白名单** `core.special.STATES`（`hypno`/`brainwash`/`no_fake`/`vibe_mood`；道具走开放前缀 `item:<名>`）、标记协议正则（`【催眠：…】`/`【洗脑：…】`/`【道具：…】`/`【不许装了】`/`【解除：…】`）、TTL 策略、感知注入格式 |
| **内容（本机文件，随你的内容包走）** | 展示名（"催眠"这类显示词）与道具默认效果文案 |

内容侧文件：**`data/special_content.json`**（UTF-8，缺文件=中性缺省，**不报错**）：

```json
{
  "labels":     { "hypno": "显示名", "item:ball": "道具显示名" },
  "item_notes": { "item:ball": "主人未给括号时的默认效果原文" }
}
```

读取链（从优先到兜底）：**主人括号原文 → `item_notes` → 内容包目录 `note` → 空**；
展示名：**`labels` → 内容包目录 `label` → kind 本身**。

> **为什么这么分**：状态白名单与标记协议是**第三方要照抄的契约**（卡与提示词都按它互通），必须公开；
> 而"这个状态该显示成什么词、默认写什么效果"是**表述**，跟内容走——这也是本项目"R18 内容不随公开仓、
> 能力与接口公开"的落地方式（见 `docs/R18分层-spec-2026-09-12.md`）。
> 注意：`状态 kind 白名单`**不是**展示名列表——把它当展示名外置会让第三方装机上整层状态机失效（`set_state` 靠它判合法）。

## 7. 常见误解（**先看这里再提问**）

| 误解 | 事实 |
|---|---|
| "包内 `sprites/` 素材会自动生效" | ❌ v1 **不自动搬运**；真实立绘位是 `launcher/cards/`（§3.9） |
| "把包放进 `data/packs/` 就热生效" | ❌ 需重启 bot，或调 `core.packs.reload()` |
| "工具包放进去就能跑" | ❌ `PACKS_ENABLE_PY` 默认关；且需声明 `permissions` |
| "皮肤能改 GAL 的背景" | ✅ 能（`GAL_SKIN`），但 `/gal/content.json` 的**既有三键后到覆盖**（§4.6；`stage` 是增量键不覆盖它们） |
| "本地人设卡会被内容包覆盖" | ❌ **本地永远优先**（`data/personas/<key>.json` 存在就用它） |
| "world 包的 `keys` 会触发设定注入" | ❌ v1 只注入 `always:true`；`keys` 是 v2 预留 |
| "表情按【基调】选图" | ❌ 【基调】只驱动**语音语气**；配图由 9 类情绪 judge 自选（两表只交一个「无语」） |
| "注册表能让模型自己选工具" | ❌ **铁律#1 明令禁止**（§6.1） |
