# 部署指南（装、升级、搬走、卸掉）

> **本文怎么用**：第一次装看 §1；想知道"哪个功能要装什么"看 §2；换电脑/换盘看 §4。
> 运维与排错见 `维护手册.md`；做 mod 见 `MOD开发指南.md`。
> **一句话前提**：**没有任何外部组件是必需的**。最小形态是"Python + 这个仓"，
> 它能跑纯文本/视觉小说模式；模型、QQ、语音、Live2D 全是可选件。

---

## 0. 三种部署形态（先选一个）

| 形态 | 你需要什么 | 得到什么 | 体积量级 |
|---|---|---|---|
| **最小（纯文本/GAL）** | Python 3.13 + venv 依赖 | GAL 页/网页模式对话；模型走外部 API（填 `LLM_BASE_URL`） | 约 170 MB |
| **标准（本地模型）** | 最小 + llama.cpp + Gemma 权重 | 离线可用；加上 embedding 后记忆语义检索 | 约 9 GB |
| **完整（QQ + 语音）** | 标准 + NapCat + GPT-SoVITS + 音色权重 | QQ 里收发消息、发语音 | 约 47 GB |

> ⚠️ **NapCat 与 GPT-SoVITS 都不能由本框架代分发**：NapCat 内含腾讯 QQ 客户端组件（再分发受限），
> GPT-SoVITS 的整合包与音色权重体积大且授权在用户侧。**本框架只检测 + 指路，不自动下载。**

## 0.5 懒人包（自己打包分发 · **只带可执行框架**）

要给朋友发"解压即用"的版本，别手压整个目录——用打包器，它**强制排除**数据库、运行状态、凭据与第三方素材：

```powershell
cd qq-bot
.venv\Scripts\python.exe tools\dev\make_lazybundle.py --tier framework --write D:\qqai-lazy
```

| 档位 | 体积 | 内容 |
|---|---|---|
| **`framework`（默认）** | **约 7.5 MB** | 源码 + 启动器 exe + 文档 + 示例包 + 包内 `安装.ps1`（一键建 venv/装依赖）与 `懒人包说明.md` |
| `standard` | ≈ 11 GB | + llama.cpp 与本地模型权重 |
| `full` | ≈ 48 GB | + GPT-SoVITS 与音色权重 |
| `--with-wheels` | + 2.4 GB | torch 缓存（只在做模型转换 / LoRA 训练时需要） |
| `--with-private` / `--with-restricted` | — | 带上第三方素材（角色卡/方舟皮肤/表情包）/ NapCat —— ⚠️ **只可私下传，不可公开发布** |

**永不入包**（任何档位、任何开关都不豁免）：`data\memory.db`、`agent_checkpoints.db`、`data\*.json` 运行状态、
`.env` 凭据、`qq-bot\.venv`（内含绝对路径，换机必失效）、日志、`vault\`。

> 收包的人需要自备两样：**Python 3.13**，以及**一个模型或一个 API Key**（外部 API 是设计内的正路，不算降级）。
> 对外**公开发布**请用官方发行包（SDK / Core / 启动器三件，见仓库 Releases），不要发懒人包。

## 1. 全新安装

> **先分清两种来源**（2026-09-12 补：这两条路拿到的东西不一样，混着说会让人以为"少了东西"）：
>
> | 来源 | 有什么 | 没有什么（要自备/自建） |
> |---|---|---|
> | **克隆本仓 / 下源码包** | 全部源码、`qq-bot\packs\` 的七类示例包、出厂占位人设 `_starter`、WebView2 的 **4 个包装 DLL**（`launcher\*.dll`） | **`QQAI-Launcher.exe`（构建产物）**、模型、语音权重、NapCat；WebView2 **运行时本体**另外两者都不带（用系统的，见下） |
> | **懒人包 / 发行包**（Releases） | 上表全部 **＋ 预编译 exe ＋（懒人包）`安装.ps1`** | 模型、语音权重、NapCat（许可与体积所限，永不随包） |
>
> 克隆用户启动器入口 = **`launcher\Run.bat`**（exe 不在时它自动回落到 `Launcher.ps1`，无需管理权）；
> WebView2 **运行时本体**用**系统 Evergreen**（Win10/11 多半已内置；项目不分发它——`launcher\webview2\` 里是 SDK 的 nupkg，不是可直接用的运行时）。缺什么、缺了会怎样、去哪拿：
> 打开启动器看**「组件」页**，或跑 `launcher\Launcher.ps1 -Mode deps`。

```powershell
# ① 放好目录（本指南以 <安装根> 指代这个目录）
#    把仓库解压/克隆到任意路径，例如 E:\robot —— 路径不再被硬编码（2026-09-12 起由 core/paths.py 推导）

# ② 建 Python 环境
cd <安装根>\qq-bot
python -m venv .venv
.venv\Scripts\python.exe -m pip install -U pip
.venv\Scripts\python.exe -m pip install -e .        # 依赖清单见 pyproject.toml

# ③ 配置身份（**必做**，否则 bot 起不来）
copy .env.example .env
notepad .env
#   SUPERUSERS=["你的QQ号"]      ← 必须是 JSON 数组（裸数字会让 bot 起不来，见维护手册 §4.1）
#   OWNER_NICKNAME=你的昵称       ← 不填会回落中性默认串
#   PERSONA=_starter             ← 出厂占位人设（随仓）；换成自己的卡就改这一行，或私聊 /人设 卡名

# ④ 启动（会自动按需拉起引擎/NapCat）
cd <安装根>
.\start.bat
```

**验证装好了**：

```powershell
<安装根>\launcher\Launcher.ps1 -Mode status     # 或直接看启动器「运行状态」页
```

四灯（引擎 / 记忆 / QQ / 机器人）里**只有「机器人」是必须亮的**——其余三盏灭着，项目依然可用。

## 2.5 QQ 通道接入（可选 · NapCat）

> **本框架不代分发、不自动下载 NapCat**——它内含腾讯 QQ 客户端组件，再分发受限。
> 上游：`https://github.com/NapNeko/NapCatQQ`（混合许可，见 `THIRD_PARTY.md`）。
> 本节内容原先只写在 `<安装根>\tools\NapCat对接说明.md`——那份**在 gitignored 的 `tools\` 下，
> 不随发行物分发**，故内联到此（照原样，只去掉硬编码盘符）。

**① 解压运行**

1. 把上游 NapCat 包解压到 `<安装根>\tools\napcat\`
2. 运行其中的 `napcat.exe`（或 `launcher.bat`）
3. **用机器人 QQ 小号扫码登录**（唯一必须人工参与的步骤）

> NapCat 5.x 启动后可在浏览器访问 `http://127.0.0.1:6099/webui`（WebUI 管理）；
> 登录后会生成 `napcat/config/onebot11_<QQ号>.json`。

**② 配置 OneBot v11（在 WebUI 改，或直接编辑那个 json）**

```json
{
  "network": {
    "enable": true, "name": "qq-bot", "type": "websocket_server",
    "host": "127.0.0.1", "port": 8080,
    "messagePostFormat": "array", "enableHeartbeat": true
  },
  "http": { "enable": false },
  "httpPost": { "enable": false }
}
```

即：**NapCat 作为 `websocket_server` 监听 `127.0.0.1:8080`，bot 反向连接到 `ws://127.0.0.1:8080/onebot/v11/ws`**
（与 bot 的 HTTP 同端口——这是 nonebot 反向连接的默认端口）。

**③ 验证**

- bot 日志出现 `WebSocket reverse connection ... connected` 即打通
- 私聊机器人发任意消息 → 应有回复；群里 @机器人 → 应有回复

**④ 风险提示**（照原样保留，这不是免责套话）

- 非官方协议：**请用小号、控制频率**
- 若被封：换号 + 降低触发频率；本项目配置与数据分离，换号只需重新登录 NapCat（不必重装）

## 2.6 Telegram 通道（可选 · 国际 IM · 2026-09-12 接入）

> **为什么有这条**：海外没有 QQ，而 Telegram 的官方 Bot API 最宽松（BotFather 拿 token 即用）。
> 这条通道让本项目在**完全没装 QQ / NapCat** 的机器上也能对话——`docs/部署指南.md §2` 的矩阵里
> 「QQ 通道」那一行的降级路径就是它。接入范式与 GAL 页**同一条路**（合成 OneBot 事件进同一条管线），
> 所以它与 QQ、GAL 页**共用同一份主人身份与记忆**（同 uid、同好感、同人生状态）。

**① 建 bot（只做一次，约 1 分钟）**

1. Telegram 里找 **@BotFather** → 发 `/newbot` → 起名 → 拿到 `<数字>:<串>` 形式的 token
2. 找 **@userinfobot** → 给它发任意一条消息 → 它回你自己的**数字 id**（不是 @用户名）

**② 写配置**（`qq-bot\.env`；改完**重启 bot**）

```ini
TELEGRAM_ENABLED=true
TELEGRAM_BOT_TOKEN=123456789:AAxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
TELEGRAM_OWNER_ID=123456789
# 直连 api.telegram.org 不通时才填（中国大陆常见）：本机代理，如 http://127.0.0.1:10808
TELEGRAM_PROXY=
# 自建反代才改（⚠️ 第三方反代会看到你的 token）
TELEGRAM_API_BASE=https://api.telegram.org
```

**③ 验证**

- bot 日志出现 `telegram 通道已启动：owner=… api_base=…` 即打通
- 用**该 id 对应的账号**私聊这个 bot → 应有回复
- 配置不全**不会静默死**：日志明确写出缺哪一个键（`telegram 已启用但配置不全，通道未启动 —— 缺：…`）
- 想在不建 bot 的前提下验证整链：`qq-bot\tools\dev\tg_loop_check.py`（本地 mock Bot API 服务器，
  跑通长轮询 → 门 → 合成事件 → 出站，不需要真 token）

**④ 边界（v1 明确不做，不是漏；逐条对应遗留任务编号）**

| 项 | 现状 | 原因 |
|---|---|---|
| 群聊 | **忽略**（日志可见，不回复） | 需要"只在被 @"规则与群级状态，见 A17 |
| 陌生人私聊 | **忽略**（不回复、不解释） | 否则猜中 bot 用户名的人就能**当成你本人**说话（记忆、人设、API 额度一起交出去） |
| 语音 | 只入不出：她能"察觉"你发了语音，回复只发文字 | QQ 侧发的是 silk base64，Telegram 要 ogg/opus，需在 voice 侧留存 wav 再转码 → A15 |
| 图片 | 出站可发（表情包/搜索图）；入站只做**存在感知**（知道"你发了张图"，但看不懂内容） | 不拉入站图片字节：避免把带 token 的 TG 文件 URL 写进历史与提示词 |
| 离线期间的消息 | 启动时**跳过**（日志报条数，不补答） | 开机被几十条旧消息刷屏、且每条都烧 LLM 额度，代价大于"少回几条旧消息" |
| 启动器界面开关 | **暂无**，只能手工改 `.env` | 见 A16 |

**⑤ 关闭** = `TELEGRAM_ENABLED=false`（或整行删掉）。插件仍在加载清单里，但**零副作用**：
不建连接、不打日志、不占端口（实测：关闭态除 nonebot 自己那行加载日志外无任何输出）。

## 2.7 在线 API 模式：引擎还必选吗？一个月多少钱？（2026-09-12 本机实测）

> 回答两个实际问题：**切到在线 API 后本地模型还要不要、显存能不能省出来**，以及**大概烧多少钱**。
> 数字全部实测，工具可复现：`qq-bot\tools\dev\llm_meter.py`（替身客户端 + 真库副本，不出网、不花钱、不动真库）。

### 2.7.1 排查：选了 API，还会拉本地模型吗

| 问题 | 结论 | 证据 |
|---|---|---|
| 本地引擎是否**必选** | **不是**：`launcher/deps.json` 里 `required:false`，状态页渲染为「可选」，§2 矩阵写明"改为连外部 API：**这是设计内的正路，不是降级**" | `deps.json` → `features[1]` |
| 选 API 后启动器**还会不会拉起**引擎 | **会**——`New-StartSteps` 只看「启动引擎」开关，**不看 provider**：开关开着就照启 llama-server（`-ngl 99`，吃满显存） | `Launcher.ps1`：`if ($cfg.llm) { Start-Engine; Start-Embedding }` |
| ⚠️ 连带效应（隐蔽） | 同一个 `if ($cfg.llm)` 块里**同时**启记忆向量服务（11435）：**关掉这个开关会连带丢掉语义检索**（记忆回落关键词匹配） | 同上 |
| 记忆向量吃显存吗 | **不吃**：embedding 是第二个 llama-server，参数带 `-ngl 0`（CPU 推理） | `Launcher.ps1` `Start-Embedding` |
| 还有谁偷偷依赖本地 11434 | 三处：① `plugins/voice` 的两处 LLM 润色（失败回落原文，但会白等超时）② `brain` 的模型切换命令（会尝试拉本地引擎）③ `.env.example` 里**注释形态**的 `LLM_SMALL_BASE_URL=http://127.0.0.1:11434/v1`——照着取消注释，小模型链就重新依赖本地引擎 | 各自源码 |
| 小模型链默认去哪 | 不设 `LLM_SMALL_BASE_URL` 时**回落主链**（= 你选的 API），无需本地引擎 | `core/llm.py` `base_url("small")` |

**建议**：只用 API 就**别启动本地聊天引擎**；但注意上面的连带效应——若你还想保留语义检索，
应改成"只跳过聊天引擎、保留 embedding"，这属**改变启动器默认行为**，已挂 `遗留任务.md` A18 等你点头。

### 2.7.2 实测：一条消息花多少钱

**实测方法**：用**真历史**（`data/memory.db` 副本）驱动一轮真实私聊，把 LLM 客户端换成**只记录不发送**的替身
→ 得到"brain 真实组装出来的 prompt 到底多大、一回合几次调用"，且不出网、不花钱、不动真库。

**一轮私聊 = 6 次 LLM 调用，prompt 合计 ≈ 13,851 tok**：

| # | 用途 | system | 对话 | prompt≈ | 说明 |
|---|---|---|---|---|---|
| 1 | `agent` | 2,274 字 | 267 字 | 1,295 tok | 决策/规划 |
| 2 | `correction` | 390 字 | 13 字 | 183 tok | 矫正规则判定 |
| 3 | `main` stage1 | **9,882 字** | 787 字（17 条消息含历史） | **5,297 tok** | 正文（思考+草稿） |
| 4 | `main` stage2 | **9,853 字** | 248 字 | **5,049 tok** | 润色（同一份人设+记忆再发一遍） |
| 5 | `memory` | 4,333 字 | — | 1,948 tok | 记忆抽取 |
| 6 | `emotion` | 120 字 | 50 字 | 79 tok | 情绪分类 |

**价格**（DeepSeek `deepseek-flash` = V4.1-Flash，官方价目 2026-09-12；元/百万 tok）：

| 项 | 高峰 | 空闲 |
|---|---|---|
| 输入·缓存命中 | 0.04 | 0.02 |
| 输入·缓存未命中 | 2.0 | 1.0 |
| 输出 | 8.0 | 4.0 |

> **高峰时段 = 北京时间周一至周五 9:00–12:00、14:00–18:00**，其余全算空闲（价 = 高峰的一半）。
> 对陪伴型 bot 是利好：**晚间、深夜、周末都在空闲档**。上下文 1M、输出上限 384K、并发 2500。

| 单条消息 | 高峰 | 空闲 |
|---|---|---|
| 输入缓存 0% 命中 | 0.029 元 | 0.014 元 |
| 50% 命中 | 0.015 元 | 0.007 元 |
| 80% 命中 | 0.007 元 | 0.003 元 |

**按你的真实日活外推**（`data/memory.db` 实测：09-09 = 254 条、09-10 = 134、09-11 = 117 条主人消息；
主链调用次数 ≈ 1.3 × 消息数——日志实测 09-11：117 条消息 / 155 次主链生成）：

| 用量 | 高峰价（80% 命中） | 空闲价（80% 命中） |
|---|---|---|
| 130 条/天 | ≈ 1.2 元/天 → **37 元/月** | ≈ 0.6 元/天 → **18 元/月** |
| 250 条/天 | ≈ 2.4 元/天 → **71 元/月** | ≈ 1.2 元/天 → **35 元/月** |

另计：生活模拟心跳（日志实测 7–20 次/天，按每次约 3k prompt tok 估）≈ 0.08 元/天，占比很小；
输出 token 是次要项（每回合按 100–250 tok 估 ≈ 0.001–0.002 元）。

### 2.7.3 三个省钱杠杆（按影响排序）

1. **缓存命中是最大杠杆**（命中/未命中差 50 倍）。本项目每回合两条主调用共享约 **9.9k 字**的"人设+记忆"系统前缀，
   这一截天然可命中——**别在系统提示最前面塞每次都变的东西**（时间戳、随机串、每轮变的统计），那会把整段缓存打掉。
2. **时段**：日复盘、长文写作、批量回放这类能等的活挪到空闲时段（价减半）。
3. **`LLM_SMALL_BASE_URL` 保持空**（回落主链）；别照 `.env.example` 的注释把它指向本地 11434。

> **口径提醒**：以上是**估算**不是账单——token 按 CJK 0.6 tok/字、其余 4 字符/tok 折算，输出长度按常见值假设。
> 真实计费以服务商为准；用一个月真实账单校正一次即可（工具会打印字符数，便于换算）。

## 4. 换盘 / 换机器（迁移）

1. **整个目录拷走**（`data\`、`qq-bot\.venv\` 都带上；`tools\` 太大可单独拷）。
2. **venv 必须重建**（里面记着绝对路径）：
   ```powershell
   cd <新安装根>\qq-bot
   rmdir /s /q .venv
   python -m venv .venv && .venv\Scripts\python.exe -m pip install -e .
   ```
3. **确认路径推导**：
   ```powershell
   <新安装根>\launcher\Launcher.ps1 -Mode status
   ```
   能打印四灯与显存即路径正常（2026-09-12 起核心路径由 `core\paths.py` 相对推导，不再写死 `E:\robot`）。
4. **重编启动器 exe**（可选，仅当你想从新路径双击 exe）：`launcher\README.md` §8。

**已知残留**（会因换盘失效，见 `遗留任务.md` C1）：
`qq-bot\plugins\voice\**` 里仍有几处硬编码 `E:\robot\...` → 换盘后语音会失效，其余功能正常。

## 5. 卸载

本框架**不写注册表、不写系统目录、不装服务**——卸载 = 删目录。

1. 先停：`stop.ps1` 或启动器「停止」（确认没有 `llama-server` / `python` / `NapCat` 残留进程）。
2. 想留记忆就备份 `data\memory.db`，想留人设就备份 `qq-bot\data\personas\`、`data\*.json`。
3. 删掉安装根目录。
4. 可选清理：VTube Studio（若为它装过）、WebView2 运行时（Win11 自带，不必删）。

## 6. 装不起来的排查顺序

| 症状 | 先查 |
|---|---|
| 双击 `start.bat` 一闪而过 | 在该目录开 PowerShell 跑 `.\start.ps1`，看红字 |
| bot 起不来、报 pydantic 校验失败 | `.env` 的 `SUPERUSERS` 不是 JSON 数组（见维护手册 §4.1） |
| 8080 起不来 | 端口被占：`netstat -ano \| findstr :8080` |
| 引擎起不来 | `data\llama-server.err.log`；显存是否被占；模型文件是否在 `data\models\` |
| 启动器白屏 | 看 `launcher\webstep.log`；WebView2 运行时是否完整 |
| 点 **GAL** 提示"机器人未启动" | 这是启动器**故意拦下**的：GAL 页由 bot 提供，8080 不通时它必然打不开。先点顶栏「▶ 启动」（引擎就绪约 30-60 秒）再进 GAL。万一 WebView 停在了加载失败页，点顶栏「主页」会自动导航回皮肤入口 |
| 组件页报"依赖矩阵缺失，无法检测" | 3.9.81 起应当不再出现：启动器改为按 exe/脚本所在位置推导自己的目录，根目录直跑 `QQAI-Launcher.exe` 与在 `launcher\` 里跑 `Launcher.ps1` 两种布局都认。若仍出现，检查 `launcher\deps.json` 是否随启动器一起在 |
| 语音不出声 | GPT-SoVITS 目录与权重路径；`data\voice_mode.json` 开关 |
| 记不住事 | `data\memory.db` 是否存在且非空；embedding 灯灭着也能用（降级为关键词） |

> **无窗口运行**：`Launcher.ps1 -Mode status|deps|packs|logs` 直接打印到控制台、不开窗（SSH/无人值守时用）。
> 注意：用 `-noConsole` 的 GUI exe 启动时，`-Mode` 的输出是**看不见的**。

更全的故障表见 `维护手册.md` §7.1。
