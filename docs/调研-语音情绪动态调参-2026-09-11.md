# 调研 · 语音情绪动态调参：社区怎么做 vs 我们现状（2026-09-11）

> 触发问题：参考音频覆盖不了所有情绪状态，语音包是不是不该纯靠参考、应该动态调参？社区怎么做的？
> 结论先行：**社区确实是"参考音频管情绪方向、动态参数管能量与稳定"的双层结构**——GPT-SoVITS 官方明确说过 embedding 式情绪控制实验失败，参考切换是社区事实标准；但动态参数那一层我们目前只用了 temperature 一个旋钮（speed 恒 1.0、top_p 没从插件侧传、repetition_penalty/seed 根本没接线），社区通行的那部分调参空间我们没有用满。真要"接入一切状态"，那是另一档引擎的事（文末对照）。

## 1. GPT-SoVITS 官方立场：情绪控制没有银弹

- 官方 roadmap 至今挂着 "Enhanced TTS emotion control" TODO（[README](https://github.com/RVC-Boss/GPT-SoVITS)）；issue #910 即情绪控制请求。
- 官方作者 RVC-Boss 在 [#1561](https://github.com/RVC-Boss/GPT-SoVITS/issues/1561) 实锤：**基于 embedding 的情感控制实验失败**（"embedding肯定是不好用了"），推荐路线="用情感数据特化训练 GPT + 情绪用不同参考音频"。
- 结构性限制（[#1093](https://github.com/RVC-Boss/GPT-SoVITS/issues/1093)）：temperature/top_p/top_k/repetition_penalty/seed **只作用于 GPT（文本→语义 token）阶段**——参数只能改变"这一档参考情绪邻域内的采样随机度"，改变不了情绪"方向"。没悲伤参考，调参调不出真悲伤。
- v3/v4 底模本身情绪表达比 v2 好（[官方 wiki 各版本特性](https://github.com/RVC-Boss/GPT-SoVITS/wiki/GPT%E2%80%90SoVITS%E2%80%90features-(%E5%90%84%E7%89%88%E6%9C%AC%E7%89%B9%E6%80%A7)）——我们已是 v4。

**社区通行手法排序**：① 多情绪参考音频切换（事实标准，官方背书）→ ② 文本侧标点技巧 → ③ 动态采样参数（辅助）→ ④ 带情绪数据微调（门槛高、少）。没有任何知名项目把"情绪→temperature 映射"当主要手段。

## 2. 本地部署的参数硬边界（实测核对，2025-05-29 v4 整合包）

本地 `api_v2.py::TTS_Request`（`tools/GPT-SoVITS-v4-package/GPT-SoVITS-v4-20250529/api_v2.py:150-172`）全部可调参数：

| 参数 | 默认 | 对语气/情绪的作用 |
|---|---|---|
| ref_audio_path + prompt_text | 必填 | **决定性**：音色+韵律+情绪基调（prompt_text 必须是参考音频逐字转写） |
| aux_ref_audio_paths | None | 辅助参考融合，稳音色，不管情绪 |
| temperature | 1 | **核心多样性旋钮**：高=起伏大易抽到激情演绎也易翻车；低=平稳 |
| top_p | 1 | 同上，与 temperature 配合 |
| top_k | 5（v4 构建） | 同上；实际项目用 20~30 不少见 |
| repetition_penalty | 1.35 | 过高压平语气、过低复读；社区普遍保持默认 |
| speed_factor | 1.0 | **唯一直接语速手段**：社区常用 0.85~1.2（>1.25 赶、<0.8 拖） |
| text_split_method | cut5 | 切分粒度影响句内韵律连贯（cut0 不切更连贯/cut5 按标点更稳） |
| seed | -1 | 抽卡/复现工具，不是情绪工具（且 SoVITS 阶段仍非完全确定） |
| sample_steps / super_sampling | 32 / False | v3/v4 vocoder 质量，与情绪无关 |
| batch_size / parallel_infer / streaming / media_type 等 | — | 纯速度/传输，无关 |

**我们的 worker 现状**（`voice_tts_worker_daemon.py`，不走 HTTP api_v2、直调 `get_tts_wav`）：
- 协议只透传 4 个旋钮：`temp / topp / speed / cut`；**top_k 写死 20**（daemon `_synth_one`）、repetition_penalty/seed/aux_refs/fragment_interval 未接线。
- **插件侧实际只用了 temp**（voice:183-198 `ZH_EMO_PARAMS` 9 类全是 `(温度, 1.0)`，speed 恒 1.0），**topp 从未发送**（daemon 落默认 0.9）。
- 已有的社区级实践（自己长出来的）：丢段重试梯子（temp±0.1 三连抽+时长完整性检查=工程化"抽卡"）、逐句合成+标点停顿表（文本侧节奏）、[VOICE] 自决标记。
- 附带事实：`_voice_request` 是请求口径单一来源（smoke 锚），加旋钮只动这一处+daemon 协议+`ZH_EMO_PARAMS` 元组扩位。

## 3. 社区档位映射经验表（归纳自 #871/#1293/2DIPW/百度云规则法；需 A/B 实测）

| 档位 | 参考选择 | speed | temperature/top_p | 文本技巧 |
|---|---|---|---|---|
| 激动/愤怒 | 激动/喊叫参考 | 1.05~1.15 | 1.0~1.1 / 0.9~1.0 | 感叹号、短句 |
| 温柔/平静 | 轻声参考 | 0.95~1.0 | 0.6~0.8 / 0.6~0.8 | 句号、逗号放慢 |
| 低落/悲伤 | 气声/低落参考 | 0.85~0.95 | 0.6~0.8 / 0.6~0.8 | 省略号（声断气连） |
| 娇俏/撒娇 | 笑意参考 | 0.95~1.05 | 0.9~1.0 | 语气词（嘛/啦/哦） |
| 疑问 | 中性参考 | 1.0 | 默认 | 问号上扬 |

标点影响韵律是社区共识（GPT 阶段理解标点、SoVITS 生成对应停顿；官方 #1260）；局限：无法控制句内停顿/重音（#651、#1609——官方从未支持 `[开心]` 类内联标记）。

## 4. 同类引擎原生情绪机制对照（要"一切状态"的真解法）

| 引擎 | 机制 | 粒度 |
|---|---|---|
| CosyVoice 2/3 | **自然语言指令**控语气（"用开心的语气说"）+ `[laughter]`/`<strong>` 标记；v3=5000h 指令数据 100+ 指令类型 | 句级指令+字级标记 |
| IndexTTS 2/2.5 | **情绪与音色解耦**：独立情绪参考 `emo_audio_prompt` + 强度 `emo_alpha`(0~1) + 8 维情绪向量 + emo_text 自动推断 | 强度连续可调 |
| OpenAudio S1 / Fish Speech | 文本内联标记：`(angry)(sad)(excited)(whispering)(laughing)`… 新版号称 15000+ 自由标签 | 词/句级可叠加 |
| ChatTTS | `oral_(0-9)/laugh_(0-2)/break_(0-7)` 参数 + `[uv_break]/[laugh]` 标记 | 词级 |
| Bert-VITS2 | emotion embedding / CLAP 多情绪**加权混合** + sdp_ratio/noise 三参数 | 句级+连续参数 |
| **GPT-SoVITS** | ❌ 无指令、❌ 无内联标记、❌ 无强度连续控制、❌ 情绪不与音色解耦 | 只有参考切换+采样参数 |

工程集成参考（LLM 情绪标签→TTS 动态管线，都是真实开源项目）：
- [Open-LLM-VTuber PR #373](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber/pull/373)：LLM 吐 `<happy>` 标签→情绪目录**随机抽一条**参考（文件名即转写）+全局 top_k/speed——最完整的参考实现；标签同时驱动 Live2D 表情。
- [GSVI (X-T-E-R/GPT-SoVITS-Inference)](https://github.com/X-T-E-R/GPT-SoVITS-Inference)：`/tts?character=X&emotion=angry&speed=1.1` 一条 URL 完成，情绪表沿用微软 SSML 35 档，不匹配回退 default。
- [2DIPW/gpt_sovits_infer_with_emotion](https://github.com/2DIPW/gpt_sovits_infer_with_emotion)：StructBERT 八分类自动路由参考+保守全局参数（temp/top_p=0.6）。

## 5. 分层方案（按投入成本）

**层 A：零音频成本（纯动态参数+文本技巧）——推荐先做**
1. speed 从恒 1.0 改为档位差（0.9/1.0/1.1，对齐上表）；temperature 保持保守当稳定性旋钮（现值 0.85~1.0 已合理，勿再当情绪旋钮加压）。
2. 插件侧把 topp 接进协议（现 daemon 默认 0.9 从未被显式控制）；可选接线 repetition_penalty/seed（seed 固定用于复现好结果）。
3. 文本侧两条规则：悲伤档省略号保留/注入、激动档感叹号+短句（注意与既有剥标记顺序）。
4. 参考"随机抽取"：同档多条参考随机选（消单参考复读感）——kaltsit 现只有 8 条静态映射，可先在已有参考里做"默认+1"的双参考抽选。
- 收益：档位间"能量差"（快慢/稳跳）出来；局限：改不了情绪方向。

**层 B：低成本（每角色补 3~5 条情绪参考）——社区性价比天花板**
- 平静/激动/低落各 1 条起步（3~10s、prompt_text 逐字转写、文件名即转写惯例）；叠层 A 微调。娇嗔/纯H/傲娇/疑问四类缺口的正解在这里，不在调参。

**层 C：高成本（换/加引擎）**
- 要自然语言指令控语气→CosyVoice2/3；要强度连续+情绪音色解耦→IndexTTS2；要内联标记/拟声→OpenAudio S1。代价：音色重克隆、显存、两套情绪词表映射。
