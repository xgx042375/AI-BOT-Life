# 皮肤包接口规范 v1（launcher-skin-v1）

> 2026-09-10 Phase 2 通用化改造产物。本文档描述 QQ AI 启动器（Launcher.ps1 / QQAI-Launcher.exe）
> 与 WebView2 主页皮肤包之间的全部接口：目录布局、manifest、state.json 数据契约、
> PS↔web 命令通道、虚拟主机映射、卡片数据源、GAL 页皮肤钩子。
> 所有字段均从实码提取（Launcher.ps1 / web/app.js / skins/arknights/bridge.js），无臆测字段。

## 1. 定位与目录布局

皮肤包 = `launcher/web/skins/<name>/` 下的自包含目录（页面 + 素材 + manifest）。
启动器按 `data/launcher.json` 的 `skin` 键选择活动皮肤；皮肤目录缺失时自动回落 `generic`。

```
launcher/web/                          ← WebView2 虚拟主机 app.local 的根
├─ index.html / home.css / app.js      ← generic 默认主页（皮肤本体在 web 根上，见 entry 说明）
├─ gal.html / gal.js / gal.css         ← GAL 页（bot serve: http://127.0.0.1:8080/gal，与皮肤无关）
├─ state.json                          ← 运行时状态（gitignore，Push-Web 整体覆写）
└─ skins/
   ├─ generic/                         ← 内置默认皮肤（跟踪）：manifest.json + palette.css + README.md
   └─ arknights/                       ← 方舟样板皮肤（gitignore，公开发行不带）：完整 SPA + ui/ 素材 + manifest.json
```

- **entry / statePath 相对路径规则**：均相对皮肤目录自身解析。
  - generic 的页面本体放在 web 根（历史布局），故 `entry:"../../index.html"`、`statePath:"../../state.json"` 回指 web 根；
  - arknights 全套自包含，`entry:"index.html"`、`statePath:"state.json"` 指向皮肤目录内。
- **`entry` 字段现状（如实）**：launcher 实际导航走 `Get-SkinEntryUrl` 推导（generic → `https://app.local/index.html`；自包含皮肤 → `https://app.local/skins/<name>/index.html`）——**entry 的取值现状被忽略**，入口文件必须命名为 `index.html`；entry 字段作为声明保留（v2 候选：真读 entry，二选一定稿）。
- **generic 样板 manifest 是纯样板**：generic 皮肤由代码内置渲染，运行时 `Get-SkinManifest` 对 generic 读的是 **web 根**的 `manifest.json`（web 根无此文件 → 回落内置默认哈希）——`skins/generic/manifest.json` 本身**不被读取**，仅供皮肤作者对照字段集合，改它不会改变 generic 外观。
- **app.local 虚拟主机**：`https://app.local/…` 即 `launcher/web/` 目录，skins 子树天然可达
  （如 `https://app.local/skins/arknights/index.html`）。
- 页面内引用素材一律用 app.local 绝对地址或皮肤目录内相对路径；`http://127.0.0.1:8080` 仅用于 GAL 页与 bot HTTP 通道。

## 2. manifest schema（launcher-skin-v1）

manifest.json 为皮肤目录下的 `manifest.json`，UTF-8 无 BOM。字段集合固定（两份内置样板字段完全一致）：

| 字段 | 类型 | 说明 | generic 样板值 | arknights 样板值 |
|---|---|---|---|---|
| `spec` | string | 规范版本，固定 `launcher-skin-v1` | 同左 | 同左 |
| `name` | string | 皮肤标识（=目录名，launcher.json `skin` 键的取值） | `generic` | `arknights` |
| `title` | string | 显示名（设置页下拉） | `简洁控制台` | `示例皮肤`（脱敏示例值，见下注） |
| `entry` | string | 入口页，相对皮肤目录 | `../../index.html` | `index.html` |
| `palette.bg` | string | 底色（HEX；WPF 窗口 Background 纯色刷取此色） | `#0f1216` | `#0D0F12` |
| `palette.fg` | string | 主文字色 | `#e8eaed` | `#E6E1D4` |
| `palette.accent` | string | 强调色 | `#4da3ff` | `#F5A623` |
| `palette.muted` | string | 次级文字色 | `#8a919c` | `#8A93A0` |
| `statePath` | string | 运行时 state.json，相对皮肤目录（信息性字段，轮询以页面所在目录为准） | `../../state.json` | `state.json` |
| `operaPage` | bool | **皮肤是否自带「干员」页**（可选，缺省 false）。true = 框架顶栏「干员」与 `cmd:"operators"` 都打开皮肤自己的干员视图（推 `page:"opera"`，由皮肤渲染）；false/缺省 = 框架原生干员页兜底。皮肤自绘的干员界面**优先于**框架那张 | 缺省（false） | `true` |
| `author` | string | 作者（可空） | `""` | `""` |
| `license` | string | 许可标识 | `MIT` | `MIT` |
| `note` | string | 备注（可空） | 内置默认皮肤说明 | 指向本文档 |

读取方：`Get-SkinManifest`（no-BOM UTF8 读，解析失败/文件缺失回落内置默认哈希）；`Get-SkinDir` 返回活动皮肤目录；
`Get-SkinEntryUrl` 返回入口页导航 URL（`https://app.local/index.html` 或 `https://app.local/skins/<name>/index.html`）。

> 注（示例值口径）：右列（arknights 样板）在本文中一律以**脱敏示例值**书写（`示例皮肤`/`示例角色`/`EXAMPLE-UNI` 等）。
> 该样板皮肤为第三方游戏 UI 复刻，gitignore、**不随任何公开发行物分发**；真实字段值以本机 gitignored 的 manifest 为准。

## 3. state.json 数据契约

Push-Web 是唯一写者：整体覆写（WriteAllText，非原子；轮询侧 JSON 解析失败静默跳过本帧，3s 后自然恢复；UTF-8 无 BOM）到**活动皮肤目录**下的 `state.json`，约每 3 秒一次（另在操作步进后即时触发）；
页面脚本每 **1 秒**轮询**页面同目录**的 `state.json?t=<毫秒时间戳>`（`?t=` 防缓存，不可省略）。

完整字段（单条 JSON 示例后附）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `__push` | bool | 恒 `true`；推送标记（PS 侧 PostWebMessageAsString 同构，页面可统一按 `__push` 过滤） |
| `stamp` | int | 每次推送自增（诊断用） |
| `pid` | int | 启动器进程 PID（pid 变化=出现双实例） |
| `time` | string | 启动器本地时间 `yyyy/MM/dd HH:mm` |
| `scene` | string | 当前场景（life_state.json） |
| `doing` | string | 正在做的事（原文，含【】段） |
| `dialog` | string | 主页对话行 = doing 去掉`【…】`后的部分 |
| `mood` | string | 心情 |
| `plan` | string | 今日计划 |
| `wake` | string | 下次心跳描述（如 `下次心跳：约 12 分钟后`） |
| `name` | string | 主人昵称（运行时取 bot 配置；示例 `@owner`） |
| `star` | string | 当前人设星级（`★`×n） |
| `idtext` | string | 当前人设标识（`<卡名> · <阵营>`，无人设时 `博士 · 本地实例`） |
| `portrait` | string | 当前人设立绘 URL（`https://cards.local/<文件名>`；无则空串） |
| `page` | string | 页面指令：`home`/`opera`/`detail`（来自 web 操作回推）；`cfg`/`log`/`state` 为 WPF 原生页，web 不可见 |
| `op` | object | `{ active: bool, text: string }`——操作进行中标志（遮罩+横幅驱动） |
| `svc` | object | 四服务灯 `{ engine, embed, napcat, bot }` 四 bool（true=运行中；实码 `Launcher.ps1` Push-Web 约 :1116-1120 写入（Test-Engine/Test-Embedding/Test-NapCat/Test-Bot），消费方 `web/app.js` 约 :159-163 逐灯渲染；旧版 state.json 无此字段时页面保持灰灯） |
| `cards` | array | 人设卡载荷（见下表；无可用立绘的卡被过滤） |
| `lang` | string | 界面语言（`zh`/`en`，缺省=`zh`；2026-09-12 全局语言切换）。**皮肤应据此切换自己的文案**：generic 样板用 `data-i18n` 标记 + 一张 `STR` 表；跳 GAL 页时把这个值带上（`?lang=<值>`） |

`cards` 单条字段（`Get-CardsPayload` 实产）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `key` | string | 卡键 = personas 文件名主干（如 `example`） |
| `name` | string | 显示名 |
| `cls` | string | 职业 |
| `uni` | string | 阵营/作品 |
| `desc` | string | 一句话简介 |
| `starText` | string | 星级文本（`★`×n，注意：**不是** `star` 数值） |
| `img` | string | 半身特写 `https://cards.local/bust4w/<key>.webp` |
| `big` | string | 全身立绘 `https://cards.local/fullw/<key>.webp` |
| `rar` | string | 星级角图 `https://app.local/skins/<skin>/ui/ark/rarity_<n>.png`；**皮肤感知**：活动皮肤为 generic 时为**空串**（前端判空跳过不渲染，无破图；arknights 等皮肤为完整 URL） |

## 4. PS↔web 命令通道

### 4.1 JS → PS（postMessage，唯一可靠命令通道）

```js
window.chrome.webview.postMessage({ cmd: '<cmd>', data: '<字符串负载>' });
```

PS 侧 `WebMessageReceived` 把消息转 JSON 后取 `[string]$m.cmd` 与 `[string]$m.data` 交 `Handle-WebCmd`。
**`data` 恒为字符串**（setpersona 的卡键即放这里，不要嵌套对象）。
备用的 URL 通道（`https://…?cmd=<cmd>&d=<urlencoded>`，NavigationStarting/SourceChanged 解析）仅 ark 样板在用，新皮肤不必依赖。

cmd 全集（Handle-WebCmd 实码）：

| cmd | data 负载 | 行为 |
|---|---|---|
| `start` | 空 | 启动全部（引擎→记忆→NapCat→bot 步进机），遮罩横幅 `⚠（正在启动全部…）` |
| `stop` | 空 | 停止全部（含 LLM，释放显存） |
| `stopbot` | 空 | 仅停机器人（LLM 保持） |
| `exit` | 空 | 停止全部后关窗退出（窗口关=Exit(0)） |
| `opera` | 空 | 切回主页 web 视图并推 `page:"opera"`（**交给皮肤**处理：如滚动到人设区；皮肤不得自绘第二套人设面，见 §9） |
| `operators` | 空 | 打开「干员」：皮肤自带干员页（manifest `operaPage: true`）时开**皮肤自己的**视图（等效 `opera`），否则框架原生页兜底（§9） |
| `deps` | 空 | 打开框架原生**组件页**（框架能力检测 / 依赖矩阵 / 一键下载） |
| `about` | 空 | 打开框架原生**关于页**（框架 / 当前皮肤 / 来源三区，含双重署名） |
| `cfg` | 空 | 打开 WPF 原生设置页（web 被整页遮盖） |
| `log` | 空 | 打开 WPF 原生日志页 |
| `state` | 空 | 清探测缓存并打开 WPF 原生状态页 |
| `home` | 空 | 切回主页 web 视图并推 `page:"home"` |
| `setpersona` | **卡键字符串** | POST `http://127.0.0.1:8080/launcher/persona`，body `{"name":"<卡键>","uid":"<主人QQ>"}`；bot 在线切换；通道不通时兜底写 `persona_select.json`（重启 bot 生效） |

另有保留字：`diag`（整条消息 JSON 落 web_diag.log）、`hb`（心跳空操作）——皮肤无需使用。

### 4.2 PS → JS（双通道）

1. **state.json 轮询**（主通道，见 §3，1 秒）；
2. **即时推送**：`PostWebMessageAsString('{"__push":true,"dialog":"…"}')`（操作提示即时反馈）与
   `ExecuteScriptAsync("showWebBlock('<文字>')") / ExecuteScriptAsync("hideWebBlock()")` 直呼。
   因此**皮肤必须提供同名全局函数**：

```js
window.showWebBlock = function (text) { /* 全屏遮罩 + ⚠ 横幅，text 去掉 ⚠/括号装饰后显示；空值用默认文案 */ };
window.hideWebBlock = function () { /* 同时收起遮罩与横幅 */ };
```

`op.active` 轮询与 PS 直呼互为冗余（任一先到都生效）；横幅文案装饰（`⚠（…）`）由皮肤自行剥离，
参照 `web/app.js` 的正则处理。

### 4.3 page 字段的皮肤侧处理

`page` 仅 `home`/`opera`/`detail` 三值会呈现在 web 视图（其余是 WPF 原生页，web 被整页遮盖）；
`page` 变化才应用一次，防推送重放抖动。

**收到 `opera` 该做什么**：**自绘了干员表的皮肤**把它映射到自己的视图（arknights：`#view-opera`，
并在 manifest 写 `operaPage: true`）；**没有自绘**的皮肤把它转交框架兜底页
（`postMessage({cmd:'operators'})`，generic 样板就是这么做的）。两种写法都对——§9 只要求
"同一批数据别摆两套界面"，不要求归属必须是框架。

## 6. 卡片数据源：data/cards.json

`Get-Cards` 的读取顺序：`data/cards.json` 存在且解析成功 → 用之；否则内置表 `$CARDS_FALLBACK`（17 条原样保留），
并在首次运行时用内置表导出一份初始 `data/cards.json`（UTF-8 无 BOM，`ConvertTo-Json -Depth 4`）。

格式：JSON 数组，元素字段固定 6 个——

```json
[
  { "key": "example", "name": "示例角色", "cls": "术师", "star": 6, "uni": "EXAMPLE-UNI", "desc": "示例组织领袖 · 温柔坚定" }
]
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `key` | string | 卡键（personas 文件名主干；立绘文件名亦由此派生） |
| `name` | string | 显示名 |
| `cls` | string | 职业 |
| `star` | int | 星级 1-6（`starText`/`rar` 角图由它派生） |
| `uni` | string | 阵营/作品 |
| `desc` | string | 一句话简介 |

**新卡免重编译**：exe 内只编译了回退表；运行时卡片以 `data/cards.json` 为准——新增人设卡只需
① 仿上表追加一条 JSON；② 放入立绘 `launcher/cards/<key>_full.png`（全身）等素材（见 launcher/README §9）；
③ 重启启动器（web 卡网格与 WPF 干员页同源 `Get-Cards`）。

## 7. GAL 页皮肤钩子（预留接口）

gal.js 顶部素材口 `ASSETS`（背景/立绘 baseURL/scene→背景映射等）支持皮肤覆盖：**在 gal.js 加载之前**定义

```js
window.GAL_SKIN = { assets: { bgDefault: 'https://app.local/skins/<skin>/img/x.png', /* …与 ASSETS 同形… */ } };
```

gal.js 载入即执行（Phase 2 已实现）：

```js
if (window.GAL_SKIN && window.GAL_SKIN.assets) { Object.assign(ASSETS, window.GAL_SKIN.assets); }
```

未定义 `GAL_SKIN` 时走内置默认（方舟背景，图挂 onerror 渐变兜底）。Phase 2 仅立约定，无内置调用方。

补两句现状（如实）：

- **与 `/gal/content.json` 的覆盖先后**：gal.js 载入即执行 `GAL_SKIN.assets` 的 `Object.assign`，而 `/gal/content.json` 是启动后异步拉取、**后到覆盖**——content.json 携带的 `quotesByCard` / `quoteFallback` / `spriteMap` 三键会覆盖皮肤值（仅此三键；背景等其余素材键不拉取、皮肤值不受影响）。**三键的落点不同（2026-09-12 订正）**：`quotesByCard` 与 `spriteMap` 就在 `ASSETS` 上，`Object.assign` 即生效；`quoteFallback` 的读点是模块变量（`rollQuote` 里 `ASSETS.quotesByCard[键] || QUOTES_FALLBACK`），原先**写它静默无效**，现已单列一行采纳（`GAL_SKIN.assets.quoteFallback` 且为数组时赋值给该变量）。皮肤想接管这三键时需知晓该先后，当前无豁免机制。
- **皮肤向 GAL 页注入 `GAL_SKIN` 的通道现状：无内置通道**。gal.html 由 bot serve（`http://127.0.0.1:8080/gal`），不读皮肤 manifest、也没有皮肤 → 页面的 `<script>` 注入机制；`GAL_SKIN` 目前是**预留约定**（宿主具备 WebView2 本地页脚本注入能力时可自行定义）。bot serve 侧何时提供皮肤向导通道，属后续立项。

## 8. 方舟样板皮肤说明

本机 `launcher/web/skins/arknights/` 是按本规范整理的**样板皮肤**（.gitignore，**公开发行不带**）：
内含 arknights-ui 上游 SPA（index/detail/opera.html、css/、js/、bridge.js、zz_autorun.js）、
上游 LICENSE/CNAME/.gitattributes/README/screenshot、`img/` 场景图，以及 `ui/`
（原 `launcher/ui/ark/*` 星级图与顶栏图 + `home_bg.png` 窗口背景图 + 两张模板 jpg）。

自制皮肤最小步骤：

1. 新建 `launcher/web/skins/<name>/`，写 `manifest.json`（§2 字段集合一字不差）；
2. 页面实现 §3/§4 契约：1 秒轮询同目录 `state.json?t=`、提供 `window.showWebBlock/hideWebBlock`、
   命令用 `postMessage({cmd,data})`（样板参考 `web/app.js`，约 230 行 vanilla JS）；
3. `data/launcher.json` 的 `skin` 键设为 `<name>`，或在启动器「设置 → 皮肤」下拉切换（保存即时重导航）；
4. 皮肤目录缺失时启动器自动回落 generic（boot_err.log 留痕），不会白屏。

## 9. 分层：谁负责什么（皮肤与框架的边界）

**这一节是规范，不是风格建议。** 2026-09-12 用户实测报告："顶部按钮与主页按钮重复，
新增加了一个不一样的干员页面"——两个现象同一个根因：**框架与皮肤都在实现同一件事**。

### 9.1 分工表

| 层 | 拥有什么 | 不做什么 |
|---|---|---|
| **框架顶栏**（常驻，与皮肤无关） | 唯一导航（主页 / 干员 / 设置 / 内容包 / 运行状态 / 日志 / 组件 / 关于）+ 全局操作（▶ 启动 / ■ 停止 / ✕ 退出）+ 四服务灯 + 时钟 | 不替皮肤决定外观；**不顶替皮肤自己做的页面** |
| **框架二级页**（WPF 原生） | 设置 / 内容包（四类 + 详情栏）/ 运行状态（服务灯 + 心跳时间线 + 仅停机器人）/ 日志 / 组件 / 关于；干员页**仅在皮肤没提供时**兜底 | 不抢皮肤已提供的视图 |
| **皮肤主页**（WebView2） | 只读氛围与总览（立绘 / 场景 / 心情 / 计划 / 台词 / 服务灯）＋ 自己的视图（如自绘干员一览、GAL 页）＋ **跳转**框架页的入口（`postMessage({cmd})`） | **不重复**框架的全局操作（启动/停止/退出）；同一件事不做两套（要么自己做、要么全交给框架） |

### 9.2 三条硬规则

1. **一个动作只有一处实现**。启动 / 停止 / 退出等全局操作在顶栏是"一等公民"；
   皮肤再摆一个同名按钮 = 两个入口的状态迟早对不上（一边转圈、另一边还写着"启动"），
   而且换皮肤/删皮肤时"能不能用"就变了——这正是顶栏当初存在的理由（`启动器UI规划.md` §1 P1）。
2. **同一批数据不出现两套界面，但"用哪一套"由皮肤说了算**：
   皮肤自带某个视图（如干员页）→ **皮肤的那套是正主**（manifest `operaPage: true`，
   框架顶栏「干员」与 `cmd:"operators"` 都会打开它）；皮肤没提供 → 框架原生页兜底。
   反过来说：**皮肤提供了，就不要再让用户看到框架那张**——两个长得不一样的"干员页"正是用户报的问题。
3. **框架能力不依赖皮肤存活**。任何"只在某个皮肤里才存在"的功能都是缺陷：
   `stopbot`（仅停机器人）原先就是这样，现已补进框架「运行状态」页（`BtnStopBotOnly`）。
   ⚠️ 与规则 2 不冲突：规则 2 说的是**视图/页面的归属**，规则 3 说的是**功能不许只有一处皮肤入口**。

### 9.3 为什么值得为它加通道而不是各画一套

`operators` / `deps` / `about` 三个 cmd 原是缺口（顶栏能点、皮肤发名字却**静默无效**）：皮肤想做点什么都只能
自己再画一套，而第二套必然与框架那份逐渐分叉。补通道的成本是 3 行派发 + 文档两行；
不补的成本由**每个皮肤作者重复支付**。

> **订正（2026-09-12，当天）**：第一版补通道时我把方向写反了——写成"数据面只保留框架那份，
> 皮肤只许只读+跳转"，并据此把方舟皮肤自绘的干员页入口改去开框架原生页。
> 用户的干员页是**他自己设计的界面**，被框架页顶替掉是错的（用户当场指出）。
> 现规则为"**皮肤自带就用皮肤的，框架页兜底**"，两套皮肤都无需为这件事打补丁。
> 教训一句话：**分层是为了消除重复，不是为了统一归属**——判断"该删哪一个"要看谁的作品、谁在用。

### 9.4 皮肤做得到的事（合规清单）

- 只读展示 `state.json` 的任何字段（§3）；
- 用 `cmd` 打开任意框架页（§4.1 全集，含 `operators` / `deps` / `about`）；
- 展示自己的氛围素材、动效、布局；**自绘自己的视图**（声明在 manifest，框架会优先用它）；
- 首页放"干员"这类入口按钮：自己的页就连自己的页，没有就走 `cmd:"operators"` 让框架兜底。
