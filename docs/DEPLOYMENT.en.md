# Deployment Guide (install · upgrade · relocate · uninstall)

> **How to use this document**: first install → §1. "which feature needs what" → §2. Moving to another machine/disk → §4.
> Operations & troubleshooting: see [`MAINTENANCE.en.md`](MAINTENANCE.en.md). Building a mod: see [`MODDING.en.md`](MODDING.en.md).
> **One-line premise**: **no external component is mandatory.** The minimal form is "Python + this repo",
> which can run in plain-text / visual-novel mode. Models, QQ, TTS and Live2D are all optional.

> **Language note**: the Chinese originals in `docs/` are the authoritative, actively-maintained versions.
> This English file covers the parts an English-speaking user needs to get running. When in doubt, the Chinese
> file wins. Deep API/ops docs are being translated in stages.

---

## 0. Three deployment shapes (pick one)

| Shape | What you need | What you get | Size |
|---|---|---|---|
| **Minimal (text / GAL)** | Python 3.13 + venv deps | GAL web client + web-mode chat; the model comes from an external API (`LLM_BASE_URL`) | ~170 MB |
| **Standard (local model)** | Minimal + llama.cpp + Gemma weights | Works offline; with an embedding model, semantic memory recall | ~9 GB |
| **Full (QQ + voice)** | Standard + NapCat + GPT-SoVITS + voice weights | Send/receive in QQ, send voice messages | ~47 GB |

> ⚠️ **Neither NapCat nor GPT-SoVITS can be redistributed by this framework**: NapCat embeds Tencent QQ client
> components (redistribution restricted), and GPT-SoVITS packages/voice weights are large with licensing on the
> user's side. **This framework only detects them and points you to the source — it never auto-downloads them.**

## 1. Fresh install

> **Know which source you have first** (added 2026-09-12: the two paths do not ship the same things, and mixing them up
> makes people think files are missing):
>
> | Source | You get | You do **not** get (bring or build it yourself) |
> |---|---|---|
> | **Clone / source archive** | all sources, the seven example packs under `qq-bot\packs\`, the shipped placeholder persona `_starter`, the **four WebView2 wrapper DLLs** (`launcher\*.dll`) | **`QQAI-Launcher.exe`** (a build product), models, voice weights, NapCat; the WebView2 **browser runtime itself** is not shipped by either path (use the system one, below) |
> | **Lazy bundle / release package** (Releases) | everything above **+ a pre-built exe + (`安装.ps1`)** | models, voice weights, NapCat (licensing and size — never shipped) |
>
> For a clone, the launcher entry point is **`launcher\Run.bat`** (it falls back to `Launcher.ps1` when the exe is
> absent, and needs no admin rights). The WebView2 **browser runtime** comes from the **system Evergreen** install
> (usually already present on Win10/11; this project does not ship it — `launcher\webview2\` holds SDK nupkg files, not a
> usable fixed-version runtime). If rendering fails, see `launcher\webview2_error.log`. To see what is missing, what breaks without it and where to get it:
> the launcher's **Components** page, or `launcher\Launcher.ps1 -Mode deps`.

```powershell
# (1) Put the directory anywhere  (this guide calls it <install-root>)
#     Unzip/clone the repo to any path, e.g. E:\robot — paths are no longer hard-coded
#     (derived at runtime by core/paths.py since 2026-09-12)

# (2) Create the Python environment
cd <install-root>\qq-bot
python -m venv .venv
.venv\Scripts\python.exe -m pip install -U pip
.venv\Scripts\python.exe -m pip install -e .        # dependency list: pyproject.toml

# (3) Configure your identity  (**required**, otherwise the bot will not start)
copy .env.example .env
notepad .env
#   SUPERUSERS=["your-qq-number"]   <- MUST be a JSON array (a bare number prevents startup)
#   OWNER_NICKNAME=your-nickname    <- falls back to a neutral default if unset
#   PERSONA=_starter                <- the shipped placeholder persona; point this at your own card

# (4) Start (the launcher pulls up engine / NapCat as needed)
cd <install-root>
.\start.bat
```

**Verify the install**:

```powershell
<install-root>\launcher\Launcher.ps1 -Mode status     # or open the launcher's "Status" page
```

Of the four status lamps (engine / memory / QQ / bot), **only "bot" must be green** — with the other three off,
the project is still usable.

## 2. Feature → dependency matrix

The authoritative, **auto-generated** matrix lives in the Chinese `docs/部署指南.md` §2, and its single source of
truth is **`launcher/deps.json`** (regenerated by `qq-bot\tools\dev\sync_deps_doc.py --write`).

This English file deliberately **does not duplicate that table** — a second copy of the same facts is exactly how
drift starts (a lesson this project learned the hard way). For live status on your machine, run:

```powershell
<install-root>\launcher\Launcher.ps1 -Mode deps      # same logic the launcher's "Components" page uses
```

The design intent behind the matrix, in one paragraph: **every row except the bot itself is optional**, and every
optional row has a written degradation path. Local inference can be replaced by any OpenAI-compatible endpoint
(*this is a supported path, not a fallback*); without the embedding model, memory degrades to keyword matching;
without NapCat, the GAL web client still works (shipping with the GAL client as the main UI is a deliberate design
choice); without TTS you simply get text.

⚠️ Two upstream notes worth repeating: **model weights** and **voice weights** are *not* distributed with this
framework — obtain them legally yourself and check their own redistribution terms.

## 2.5 QQ channel (optional · NapCat)

> **This framework does not redistribute or auto-download NapCat** — it embeds Tencent QQ client components, so
> redistribution is restricted. Upstream: `https://github.com/NapNeko/NapCatQQ` (mixed license, see `THIRD_PARTY.md`).

**① Unpack and run**

1. Unzip the upstream NapCat package into `<install-root>\tools\napcat\`
2. Run `napcat.exe` (or `launcher.bat`) from there
3. **Scan the QR code with your bot account** (the only step that requires a human)

> NapCat 5.x exposes a WebUI at `http://127.0.0.1:6099/webui` after launch.
> After login it generates `napcat/config/onebot11_<QQ>.json`.

**② Configure OneBot v11** (via the WebUI, or edit that JSON directly)

```json
{
  "network": {
    "enable": true, "name": "qq-bot", "type": "websocket_server",
    "host": "127.0.0.1", "port": 8080,
    "messagePostFormat": "array", "enableHeartbeat": true
  },
  "http": { "enable": false },
  "httpPost": { "enable": false }
}
```

i.e. **NapCat listens as a `websocket_server` on `127.0.0.1:8080`, and the bot connects back to
`ws://127.0.0.1:8080/onebot/v11/ws`** (same port as the bot's HTTP API — NoneBot's default for reverse connections).

**③ Verify**

- The bot log shows `WebSocket reverse connection ... connected`
- Send any private message to the bot → it replies; @-mention it in a group → it replies

**④ Risk notes** (kept verbatim from the Chinese doc — these are not boilerplate disclaimers)

- Unofficial protocol: **use a secondary account and keep the message rate low**
- If banned: switch accounts and reduce trigger frequency. Configuration and data are separated here, so switching
  accounts only means logging into NapCat again — no reinstall.

## 3. Upgrading

| Case | How | What you lose |
|---|---|---|
| Framework update (overwrites `qq-bot/`) | Overwrite `qq-bot\` with the new release; **keep** `data\`, `qq-bot\data\`, `.env` | Nothing (all data lives in `data\`) |
| Launcher update | Replace `QQAI-Launcher.exe` in **both** `<install-root>\` and `<install-root>\launcher\` | Nothing |
| Pack / skin update | Overwrite the directory under `data\packs\` / `launcher\web\skins\` | Nothing |

**Before** any data-touching operation (uid migration, DB cleanup):

```powershell
copy <install-root>\data\memory.db <install-root>\vault\backups\memory.db.bak_before_<reason>_<date>
```

> The directory contract is what makes upgrades safe: `qq-bot/plugins/` (framework, overwritten) ·
> `data/packs/` (content packs, never overwritten) · `data/plugins/` (third-party code plugins, never overwritten) ·
> `launcher/web/skins/` (skins, never overwritten).

## 4. Relocating (another disk / another machine)

1. **Copy the whole directory** (including `data\` and `qq-bot\.venv\`; `tools\` is large and can be copied separately).
2. **Rebuild the venv** (it records absolute paths):
   ```powershell
   cd <new-root>\qq-bot
   rmdir /s /q .venv
   python -m venv .venv && .venv\Scripts\python.exe -m pip install -e .
   ```
3. **Confirm path derivation**:
   ```powershell
   <new-root>\launcher\Launcher.ps1 -Mode status
   ```
   Printing the four lamps and GPU memory means paths resolve correctly (since 2026-09-12 core paths are derived
   relative to the install root — `E:\robot` is no longer hard-coded).
4. **Rebuild the launcher exe** (optional, only if you want to double-click it from the new path): `launcher\README.md` §8.

**Known remainder**: a few hard-coded `E:\robot\...` paths still exist under `qq-bot\plugins\voice\**` → after
relocating, voice breaks while everything else keeps working.

---

## 5. Uninstalling

This framework **writes no registry keys, no system directories, and installs no services** — uninstalling = delete the directory.

1. Stop first: `stop.ps1` or the launcher's "Stop" button (make sure no `llama-server` / `python` / `NapCat` processes remain).
2. Back up what you want to keep: `data\memory.db` (memories), `qq-bot\data\personas\` and `data\*.json` (characters).
3. Delete the install root.
4. Optional cleanup: VTube Studio (if you installed it for Live2D), WebView2 runtime (bundled with Windows 11 — leave it).

## 6. Troubleshooting order

| Symptom | Check first |
|---|---|
| `start.bat` flashes and closes | Open PowerShell in that directory and run `.\start.ps1` to see the error text |
| Bot fails to start, pydantic validation error | `SUPERUSERS` in `.env` is not a JSON array |
| Port 8080 unavailable | Port in use: `netstat -ano \| findstr :8080` |
| Engine won't start | `data\llama-server.err.log`; GPU memory taken; model file present under `data\models\` |
| Launcher shows a blank page | `launcher\webstep.log`; is the WebView2 runtime complete? |
| Clicking **GAL** says "机器人未启动" (bot not started) | That is the launcher refusing to navigate on purpose: the GAL page is served by the bot, so it cannot load while port 8080 is closed. Press **▶ Start** first (30–60 s for the engine), then GAL works. If the WebView is ever left on a failed page, the top bar's **Home** navigates it back to the skin entry automatically |
| Launcher says "deps matrix missing, cannot detect" | Should no longer happen since 3.9.81 — the launcher derives its own directory from where the exe/script sits, so it works both when you run the **root** `QQAI-Launcher.exe` and when you run `launcher\Launcher.ps1` in place. If you see it, check that `launcher\deps.json` ships next to the launcher |
| No voice output | GPT-SoVITS directory and weight paths; `data\voice_mode.json` switch |
| It remembers nothing | Does `data\memory.db` exist and is it non-empty? (Memory still works with the embedding lamp off — keyword mode) |

> **Running headless**: `Launcher.ps1 -Mode status|deps|packs|logs` prints to the console without opening the window
> (useful over SSH/CI). Note that output from `-Mode` is **invisible** when you launch the `-noConsole` GUI exe.

A fuller troubleshooting table lives in [`MAINTENANCE.en.md`](MAINTENANCE.en.md) §7.1.
