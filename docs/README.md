# 文档索引（从这里开始）

> **本目录有 35 份根文档 + 46 份历史留档。你只需要先读三份。**
> 本文告诉你的唯一一件事：**想问什么，去读哪一份**——以及哪些文档已经是历史、不要再当权威。
>
> （上面这两个数字由审计 **L 项**对着实际文件核验：改完文档别忘同步这行，否则它会报 ❌。）
>
> **读到公开仓的读者请注意**：本索引里有一部分是**开发期内部文档**（交接档、遗留裁决、UI 规划、
> 历史留档等），它们**不随公开仓发布**；正文里若出现指向这些内部文档的交叉引用，属开发期留痕，
> 读不到是正常的——公开面就是代码 + 本索引里带「契约 / 操作 / 做法」三类的那几份。

## 1. 三份常驻文档（90% 的问题在这三份里）

| 文档 | 回答什么问题 | 面向谁 |
|---|---|---|
| **`维护手册.md`** | 哪个开关在哪、改了要不要重启、出问题先查什么、动库前备份什么 | 使用者 / 值班维护 |
| **`接口文档.md`** | 第三方和二次开发可以依赖什么（内容包/皮肤包/GAL 协议/代码扩展/沙箱权限） | 二次开发者 |
| **`MOD开发指南.md`** | 怎么做一个 mod：角色 / 音色 / 舞台 / 皮肤 / 世界观 / 工具包 | 内容作者 |

**加一份部署文档**：`部署指南.md`（装 / 升级 / 换盘 / 卸载 + **功能→依赖矩阵**）——
它回答的是"我要装什么才有什么"，是上面三份的入口前置。

**三份的分工原则**：`维护手册` 讲**操作**，`接口文档` 讲**契约**，`MOD开发指南` 讲**做法**。
三者不重复内容——本指南里出现"字段校验细节见接口文档"这类指路是**刻意的**，因为**同一件事写两遍必然会漂移**（这个项目历史上真 bug 大半是这类漂移：情绪词表两套、差分目录两处同源、引擎参数三源）。

## 4. 文档纪律（改代码的人必须遵守）

1. **改动用户可见行为 → 同一次改动里更新对应常驻文档**。手册不更新等于没做。
2. **同一件事只写一遍**。要引用就指路，不要复制——复制就是下一个漂移源（见 §1 那段）。
3. **`docs/archive/` 只读**：那是决策史，改它等于篡改证据。
4. **新文档先想清楚归属**：是常驻（不带日期）还是快照（带日期）？是权威还是记录？
5. **不立第二份权威**：确有必要时，先改 `§2 权威归属表`，让"谁是权威"这件事本身只有一个出处。
