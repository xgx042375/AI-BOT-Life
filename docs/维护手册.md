## 0. 五分钟上手

```
第一次安装  →  见 部署指南.md（§1 全新安装 · §2 功能→依赖矩阵 · §4 换盘迁移）
启动         →  双击 start.bat     （引擎 + embedding + NapCat + bot 一条龙）
```

## 1. 启动、停止与进程拓扑

### 1.1 三条启动路径（**行为必须一致，参数三源同步**）

| 路径 | 用途 | 说明 |
|---|---|---|
| `start.bat` | 日常一键 | 转调 `start.ps1` 后 `pause`（双击可见报错） |
| `start.ps1` | 命令行/排障 | 步骤见下；带防重复双击锁 |
| `launcher\QQAI-Launcher.exe` | GUI | 图形界面 + 设置页 + 卡片墙 + 内嵌主页/GAL 页；**"停止"需要管理员权限**（提权进程的命令行查询为 NULL） |

`start.ps1` 的步骤顺序：

```
[0/3]   清理残留机器人进程（taskkill /T /F 进程树强杀；只动 bot，不动引擎/NapCat）
[1/3]   推理引擎 llama-server（11434）——已在跑则跳过
[1.5/3] embedding 服务（11435，CPU）——记忆语义检索
[2/3]   NapCat（新窗口，首次需扫码登录）——QQ 通道
[3/3]   bot（8080）——本窗口显示日志，同时写 data\bot.log；Ctrl+C = 完全退出
```

> `start.ps1` 会先探 8080 是否释放，15 秒未释放仍尝试启动并明确提示（不笼统报"已停止"）。

### 1.2 进程拓扑与端口

| 端口 | 进程 | 作用 | 没有它会怎样 |
|---|---|---|---|
| **11434** | `llama-server.exe` | 主对话模型（Gemma 4 12B heretic Q4_K_M） | **全瘫**（除非用外部 API：见 §2.1 预设） |
| **11435** | `llama-server.exe`（第二个实例） | embedding：记忆语义检索 | 降级为关键词检索，不瘫 |
| **8080** | `python`（NoneBot2） | bot 本体 + GAL 页 HTTP/WS | 全瘫 |
| **3000/其它** | NapCat（`tools\napcat\`） | QQ 协议侧（OneBot v11 反向连接） | **仅 QQ 通道消失**；GAL/网页模式仍可用 |

> **Python 侧端口常量已有唯一来源**（2026-09-12 E 项）：`qq-bot\core\paths.py` 的
> `ENGINE_PORT` / `EMBED_PORT` / `ENGINE_URL` / `ENGINE_BASE_URL` / `EMBED_URL` / `EMBED_BASE_URL`
> —— `core\llm.py`、`plugins\brain`、`plugins\debug` 全部从这里取，改端口只改一处。
> **PS 侧**（`start.ps1` / `stop.ps1` / `Launcher.ps1` / `build_release.ps1`）无法 import Python 常量，
> 只能**对齐值** → 由 `smoke_test.py` §36 逐参数钉住（改了值要同步改那三处，否则 smoke 直接失败）。
> 机器核对：`qq-bot\tools\dev\audit_consistency.py` 的 E 项（见 §7.3）。

### 1.3 引擎启动参数（**当前权威值**）

```
-c 32768 -ngl 99 --parallel 1 -ctk q8_0 -ctv q8_0
--reasoning on --reasoning-budget 200
--repeat-penalty 1.15 --repeat-last-n 256 --spec-type ngram-simple
```

- `--parallel 1`：单槽（2026-09-08 实测 decode 16.7→32-45 tok/s）
- `--spec-type ngram-simple`：无损推测解码，零显存开销
- **改参数必须三源同步**，否则 `smoke_test.py` 会失败：① `start.ps1` ② `plugins\brain` 的 `MODELS["gemma"]["args"]`（watchdog 重启与 `/模型` 切换共用）③ `plugins\debug`
- ⚠️ `tools\start-llama-server.ps1` 是**旧脚本**（写的是 `--reasoning off`，且指向已删除的 Qwen3-14B）——**不要用它起引擎**

### 2.1 后端类型预设（10 项，**全部走 OpenAI 兼容协议**）

| 显示名 | base_url | 写入 `LLM_PROVIDER` |
|---|---|---|
| 本地引擎（local · llama-server） | `http://127.0.0.1:11434/v1` | `local` |
| OpenAI 兼容（通用） | *留空待填* | `openai_compat` |
| DeepSeek | `https://api.deepseek.com/v1` | `openai_compat` |
| 阿里云百炼 DashScope（兼容模式） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `openai_compat` |
| Ollama | `http://127.0.0.1:11434/v1` | `openai_compat` |
| vLLM / LM Studio（自建） | *留空待填* | `openai_compat` |
| OpenRouter | `https://openrouter.ai/api/v1` | `openai_compat` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `openai_compat` |
| Moonshot Kimi | `https://api.moonshot.cn/v1` | `openai_compat` |
| 自定义 / 经协议代理 | *留空待填* | `openai_compat` |

> ⚠️ **协议边界**：原生 **Anthropic Messages / Gemini generateContent** 项目**不写转换代码**——
> `core/llm.py` 只做「local / 非 local」二分。需要原生协议时：**在本机跑协议代理**
> （LiteLLM / llm-rosetta / api-protocol-converter），把**代理地址**填到「接口地址」。
> ⚠️ 非 local 端点**不会**注入 `chat_template_kwargs`（`thinking_extra`）——刻意设计，不要改。
>
> **型号名有保质期（2026-09-12 用户实测修正）**：预设里原先写的 `deepseek-chat` 早已停用，DeepSeek
> 现行**无版本号**写法是 `deepseek-flash`（V4.1 Flash）；`deepseek-reasoner` 那种"另开一个模型名表示思考档"
> 的写法也已不适用（思考档现由 `LLM_THINKING_PARAM` 这类**参数**控制）。因此本表的策略是：
> **预设只保证端点地址正确**（上表右列是这一项的唯一事实），型号名给不准的**一律留空**，
> 由设置页的「拉取型号」按端点**现取**。维护约定：往预设里写型号名必须带日期 + 依据（官方文档或
> `GET /models` 实测），否则半年后没人敢动。改预设 = 改 `launcher/Launcher.ps1` 的 `Get-ProviderPresets`。
>
> **本地 / 在线双档（2026-09-12，用户实测"切在线后再切回去没变"）**：三格只有一份 `.env`，切到在线就
> 把本地那组值覆盖掉了——切回来自然"什么都没变"。现在两套值分别存 `data/launcher.json` 的
> `llmProfiles.{local,online}`（本机 gitignored），`.env` 只承载**当前激活**的那一套；设置页下方的状态行会
> 把「`.env` 实际值 ⟷ 本档」并列出来，不一致时直接说该点哪个按钮（激活 or 存入）。
> 本地档**存空值**：空串＝未设，`core/llm.py` 的回落链给出 `http://127.0.0.1:11434/v1` + `model=gemma`
> + `key=ollama`——写死具体值反而是隐患（引擎别名变了就静默失效）。
>
> ⚠️ **静默陷阱（旧实现真踩到）**：`core/llm.py` 里 `llm_provider` **只决定要不要注入 thinking**，
> 端点取的是 `llm_base_url`——所以 `LLM_PROVIDER=local` 而 `LLM_BASE_URL` 还指着云端时，
> **请求照样发到云端**（在烧 API 且不自知）。旧实现保存时只写非空值，正是清不掉它的原因；
> 现在"激活档"会**显式写空**，状态行也会对这种组合直接报警。
>
> **全 API 模式（不需要本地引擎）**：把 `LLM_BASE_URL` 指向外部端点即可，11434 可以完全不启。
> 这是「模型非必须」的落地方式（发行为此设计：模型、QQ、语音三者皆可缺）。

> |---|---|---|
> | `E:\robot\data`（即 `core.paths.DATA_ROOT`，**gitignored**） | **状态根** | 记忆库 / 状态 JSON / 日志 / 模型 / 语音素材 |

> （只是静默读到另一份、或读到空）。写状态一律用 `core.paths.data_path()`；确实要读内容根时，
> 在那一行写上为什么（审计 I 项会把没有说明的列成 ❌）。历史遗留与分发决策见 `docs\遗留任务.md` A9。
>
> **2026-09-12 收口**：规范根那 33 处 `parents[N]` 推导已全部改为 `DATA_ROOT`（一次机械迁移 + 四道复验），
> 现在**只剩内容根的 8 处例外**（brain 2 / persona 4 / correction 1 / memory 1），每一处都带注释或 `# audit-ok:`。
> 再写 `parents[N] / "data"` 指向规范根会被 I 项判 ❌——那条 idiom 正是"深度写错就静默读空"的来源。

### 3.2.1 日志会不会把磁盘撑满？（**逐项已核**）

| 日志 | 写法 | 有无上限 |
|---|---|---|
| `data\bot.log` | loguru（`rotation=10MB, retention=3`） | ✅ 有界 |
| `data\bot_hook_trace.txt` | bot 启动时以 `"w"` 截断 | ✅ 有界 |
| `data\llama-server.log` / `.err.log` / `embedding.*.log` | `Start-Process -Redirect*`（**每次启动截断**） | ✅ 单次会话内有界 |
| `launcher\webstep.log` | 启动器 `WEBLOG` | ✅ **2026-09-12 修**：超 2 MB 保留尾部 2000 行（此前**无任何上限**，实测已涨到 9.3 MB） |
| `launcher\boot_err.log` / `web_cmd.log` | 仅崩溃/命令时追加 | ⚠️ 无上限，但写入极低频（各约 10 KB） |

**要清理时**（都可安全删除，运行时自动重建）：

```powershell
# 只删日志，不动状态与记忆
Remove-Item <安装根>\data\*.log, <安装根>\data\bot_hook_trace.txt -ErrorAction SilentlyContinue
Remove-Item <安装根>\launcher\*.log -ErrorAction SilentlyContinue
```

> ⚠️ **别删**：`data\memory.db`（记忆）、`data\*.json`（状态）、`qq-bot\data\personas\`（人设卡）。
> 日志与状态在同一目录，清理时看清楚扩展名。
>
> **建这一节的理由**：日志无界增长是"会一直长、且不在任何测试视野里"的隐藏故障。
> 2026-09-12 审计时实测 `webstep.log` 已 9.3 MB 且每次操作都在长——没有任何断言会告诉你这件事，
> 只能靠人去核对"谁写的、有没有上限"。

## 4. 身份、记忆与事实

### 4.1 主人 QQ（`SUPERUSERS`）

**必须是 JSON 数组**，不是裸字符串、也不是裸数字：

```
SUPERUSERS=["10001"]
```

启动器保存时**自动**按此格式写入（写前自校验）。手工改 `.env` 时务必照此格式。

> ⚠️ **两种错写法后果不对称**：
>
> | 写法 | bot 侧（nonebot `Config.superusers: Set[str]`） | 启动器侧 |
> |---|---|---|
> | `["10001"]` | ✅ `{'10001'}` | ✅ |
> | `10001` | ❌ **pydantic 校验失败 → bot 起不来** | 解析成功（不报错） |
> | `"10001"` | ❌ **pydantic 校验失败 → bot 起不来** | 解析成功（不报错） |
>
> **危险点**：启动器两种错写法都不报错，你在 GUI 里看不出问题——但 bot 起不来。**一律写数组**。

### 4.2 ⚠️ 改 QQ 号 = 换身份（必读）

`memory.db` 里**所有记忆/关系/事实都按 `user_id` 隔离**，JSON 状态也以 uid 为键。直接改 `.env` 会得到：记忆库全部读不到（等于全新用户）、关系数值/人设选择/思考模式/约定台账全部断链。

**正确流程**：

1. 启动器 → 设置 → 「身份」→ 改 QQ 号 → **勾选确认框** → 保存
2. 跑迁移工具（**默认 dry-run 只报告**）：
   ```
   cd E:\robot\qq-bot
   .venv\Scripts\python.exe tools\migrate_uid.py --from <旧QQ> --to <新QQ> --dry
   .venv\Scripts\python.exe tools\migrate_uid.py --from <旧QQ> --to <新QQ> --apply
   ```
3. 重启机器人
4. 抽查：`/状态` 能看到旧关系数值 = 迁移成功

工具覆盖：`memory.db` 中**所有**带 `user_id` 列的表（`PRAGMA table_info` 实测发现，当前 13 张）+
`data\*.json` 的 uid 键（只处理确实存在该键的文件）。**明确不碰** `data\agent_checkpoints.db`
（uid 编在 `thread_id` 里、checkpoint 是 msgpack BLOB，改错一字节即线程损坏）。

安全约束（工具已内置）：`--dry` 为默认；`--apply` 先全量备份到
`vault\backups\memory.db.bak_before_uidmigrate_<时间戳>`；库内改动单事务，失败整体回滚；
目标 uid 已有数据时打印警告（是合并不是覆盖）；无需迁移时空操作不备份。

### 4.3 事实（facts）的两类语义（**设计如此，不是 bug**）

## 5. 思考链（reasoning）

### 5.1 现在实际是怎么开的

| 层 | 说明 |
|---|---|
| 引擎能力 | `llama-server` 以 `--reasoning on --reasoning-budget 200` 启动（预算=单次思考最大 token） |
| 请求开关 | 每轮由 bot 决定是否注入 `chat_template_kwargs.enable_thinking`（`core/llm.py`） |
| 谁能开 | ① 用户 `/思考 开`（写 `data/think_mode.json`，持久）② bot 自标【认真】（30 分钟 TTL）③ **机器判据命中**（单向开，见下） |

### 5.2 机器判据（**单向开**：只开不关，未命中仍由 agent 自决）

满足**任一**即本轮开启思考：

1. 本轮用户消息 **> 120 字**（★ 按**字符数**算，见 §5.5 的国际化注意）
2. 本轮提到**世界观角色**（命中角色关系库）
3. **上一轮触发过硬边界重试**（内容合格但格式反复失败）

### 5.5 思维链用什么语言（2026-09-12 随全开源/国际化调整）

- **原先**：`THINK_FLOW_GENERIC` 的提示里硬编码"**用中文**……禁止英文" → 英文用户会得到中文内心独白。
- **现在**：改为"**用你和他此刻正在用的语言**"——跟随对话语言（框架本就有语言感知：`_lang_note`
  → system prompt 里的【消息语言】注记），**不新增开关**。
- **不设语言开关的理由**：跟随对话比开关自然；若某人要"恒用中文回答"，那是**卡/内容**的事
  （`response_rules` 里写一句），与"能力留框架、内容跟卡走"一致。
- ⚠️ **未处理、待裁决**：§5.2 判据 1 是**字符数**阈值——英文 120 字符仅约 20 个词，会让英文用户
  频繁误触发思考（每条命中在本地引擎上要付 10–20 s）。要国际化就得按语言折算阈值，但这属
  **长度类机器限制**，项目铁律明令"未经用户确认不得再新增长度类限制 / 停止循环调参"→ **未擅动**。

### 5.3 三态开关

启动器 → 设置 → 「生成与思考」：**自决**（默认，等价删除该 uid 键）/ **恒定开启** / **恒定关闭**。
`/思考 开|关|auto` 命令与此等价（`auto` = 自决）。

### 5.4 改 reasoning-budget（三源必须同步）

现役值 **200**。改动必须同时改三处（§1.3），`smoke_test.py` 有断言钉住"三源都是 200 且 400 不得残留"——**改了值要同步改断言**。

**历史值参考**：`400`（早期）→ `120`（09-08 实测**帮倒忙**：思考是"筛选器"，砍太短等于不过滤直接倒出，输出反而更夸张）→ `200`（09-05 后既定值）。

**代价**：本地开启思考约 **+5~6 秒**延迟（走网络 API 成本小得多）。

### 5.5 排查：为什么思考一直没开

1. `data/think_mode.json` 是否有该 uid 的 `"off"` → 用 `/思考 auto` 解开
2. 日志里 `[思维链] user=... 思考=关` → 确认是关
3. `data/llama-server.err.log` 搜 `reasoning-budget` → 若 `activated` 与 `deactivated` **紧邻成对出现**，说明通道开着但模型没产出推理内容（等于没思考）
4. 不要用 `llama-server.diag.log` 判断当前参数（历史快照）

**D/C 两项都带"分级器 + 自检"**：工具把机械可证无害的与真信号分开报，且**当场证明自己认得出坏模式**
（自检样本含正例与负例）。为什么要这样：一个"永远报 0"的检查器和不存在没有区别，
而一个把 12 处无害噪声混报成 ❌ 的检查器会让人**开始忽略它的输出**——两者都是拿工具骗自己。

D 项的三个结论桶：`清理类`（只关句柄/删临时文件）·`观测类`（只写日志）·`待查`（**必须**要么改代码写日志、
要么把"为什么失败无害"注释在 `except` 或 `pass` 那一行上）。`plugins/voice/**` 的命中单列"另会话产物"，
不计入本会话的 `待查`（见 `docs/遗留任务.md` C4）。改完一轮的判据：**待查 0 且自检 PASS**。

E 项同样分级：`定义 / 注释 / 文档串 / 已声明 / 另会话产物 / 散落`，只有 **Python 侧散落字面量**与
**跨文件重复定义**（同一常量在两个文件各定义一份 = "改了 A 忘了 B"的温床）判 ❌。PS 侧（`start.ps1` 等）
无法 import Python 常量，只列不计 —— 跨语言一致性由 smoke §36 用**实构造参数**钉住。
若某常量确实**必须**在 Python 里另写一份（例：与前端 `launcher/web/gal.js` 约定的 URL 段，另一端 Python 管不到），
就在该行或上一行写 `# audit-ok: <理由>`：它会从"散落"移到"已声明"并**照旧列在报告里**（不隐藏，只是不再算 ❌）。

**N 项的边界（有意不查，先取证后决定）**：`sqlite3.connect()` 漏 `close()`、`wave.open()`、`Image.open(BytesIO)`
这三类**不入 N**。理由是一次性进程的句柄由 OS 在退出时回收，而这三种写法在本仓几乎全在 `tools/`、`tests/`
的短命脚本里（20+ 处），真正落在常驻进程的只有 `agent/graph.py` 一处、且已正确写 `try/finally: conn.close()`
（2026-09-12 取证复核）。把它们加进检查器只会产出一屏噪声，而"一个把 20 处无害噪声混报成 ❌ 的检查器会让人
开始忽略它的输出"——这类"覆盖率更高、信噪比更差"的扩张是负收益。故 N 只纳入 `open()`（常驻进程关键路径，
且真踩过 Windows 锁文件），边界写在这里而不是靠读者猜。

**K 项的同款边界（也是取证后收手的）**：`pack.json` 的**逐字段**表（§3.1–3.8 各表首列）**不做**机器双向核对。
取证结论：那几张表的首列**混装三类东西**——裸字段名（`spec`）、字段路径（`card.name/cls/star`、`compat.core_api`、
`entries[].always`）、**包内文件名**（`card.json`、`sprites/manifest.json`）；而且这份契约由 **Python 与 PowerShell
两侧共同消费**（§3.1 明写 `title`/`author`/`license` 是启动器展示用，读它的是 `Launcher.ps1` 而不是 `core/packs.py`）。
硬凑一张比对本，实测产出 **46 条假 ❌**（全是"文档写了、代码没有"，而它们其实分别由 PS 侧读、或被文档自己标为
"仅记录/仅 tool 有意义"）。**收手比上线更对**：字段级只留给真正扁平的契约（§4.4 命令通道、§5.3 素材口、
§4.1 皮肤 manifest、§3.1 的 `type` 取值集合）。将来若真要核 `pack.json` 字段，先按"py 读的 ∪ ps 读的"建模，
再给"文档自标为仅记录"的字段一个**在文档里可解析的标记**——别用硬编码白名单。
